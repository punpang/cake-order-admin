# รีเลย์ SMS Gateway

รันบนเครื่องในบ้านที่อยู่วง LAN เดียวกับโทรศัพท์ที่เปิดแอป SMS Gateway

**ทำไมต้องมี:** คลาวด์ของระบบอยู่นอกวง LAN และเกตเวย์ใช้ใบรับรองที่สร้างเองกับ pin จึงต่อตรงจากคลาวด์ไม่ได้ รีเลย์รับคำขอจากอินเทอร์เน็ตด้วยใบรับรองที่คลาวด์เชื่อถือ แล้วส่งต่อให้โทรศัพท์จากวง LAN โดยตรวจ pin ก่อนทุกครั้ง

## สิ่งที่ต้องมี
- เครื่องที่เปิดตลอด อยู่วง LAN เดียวกับโทรศัพท์ ติดตั้ง Node.js 20 ขึ้นไป
- IP ของโทรศัพท์ (ควรล็อกไว้ที่เราเตอร์) และพอร์ตของแอป (ค่าเริ่มต้น 8443)
- pin ของแอป (หน้าหลักของแอป รูปแบบ `sha256//...`)
- ใบรับรองและคีย์ของชื่อโดเมนสาธารณะ จากผู้ออกใบรับรองที่คลาวด์เชื่อถือ (เช่น Let's Encrypt) เก็บไว้นอก repo

## รัน
```
RELAY_TLS_CERT=/path/fullchain.pem RELAY_TLS_KEY=/path/privkey.pem \
PHONE_HOST=192.168.1.50 PHONE_PORT=8443 PHONE_PIN='sha256//...' \
RELAY_PORT=6330 node tools/sms-relay/relay.mjs
```
- เราเตอร์: ตั้ง port forward พอร์ต 6330 ให้ชี้ไปที่ IP ของเครื่องรีเลย์ (เดิมชี้ไปที่โทรศัพท์) ไม่ต้องเปิดพอร์ตอื่นเพิ่ม
- เมื่อต่ออายุใบรับรองแล้ว ให้รันรีเลย์ใหม่

## เส้นทางที่อนุญาต
- `POST /v1/sms` และ `GET /v1/status` เท่านั้น เส้นทางอื่นตอบ 404 และไม่ถูกส่งต่อ
- การลบข้อความ การล้างข้อความ และการตั้งค่าไม่ถูกส่งต่อ

## ความปลอดภัย
- แนะนำให้สร้างคีย์ใหม่ระดับ "ส่งและลบ" สำหรับระบบนี้โดยเฉพาะ จะได้เพิกถอนได้โดยไม่กระทบคีย์อื่น
- จำกัด body 8 KB และ 30 คำขอต่อ IP ต่อนาที ไม่บันทึกคีย์หรือเนื้อหา SMS ลงบันทึก (บันทึกมีแค่เวลา IP เส้นทาง และสถานะ)
- พอร์ตนี้เปิดรับจากอินเทอร์เน็ต จึงให้ทำงานเฉพาะเส้นทางที่ระบุข้างบน

## ทดสอบ
```
node --test tools/sms-relay/relay.test.mjs
```
ต้องมีคำสั่ง openssl ในเครื่อง ชุดทดสอบนี้ไม่ได้อยู่ใน `npm test`
