# SMS Gateway API

เอกสารนี้อธิบาย HTTP API ของแอป SMS Gateway ที่รันบนโทรศัพท์ Android 14 ขึ้นไป

## พื้นฐาน

| หัวข้อ | รายละเอียด |
|---|---|
| Base URL | `https://<ip-ของโทรศัพท์>:<พอร์ต>` ค่าเริ่มต้นพอร์ต `8443` ดู URL จริงในหน้าหลักของแอป |
| การเข้าถึง | เฉพาะเครื่องในเครือข่าย LAN เดียวกัน (loopback, RFC1918, ULA, link-local) |
| การยืนยันตัวตน | ส่ง header `Authorization: Bearer <api-key>` ทุกคำขอ |
| รูปแบบข้อมูล | JSON ทั้งคำขอและคำตอบ |
| ขนาด body | สูงสุด 8 KB |
| การส่งข้อมูลแบบ chunked | ไม่รองรับ ต้องระบุ `Content-Length` |
| Rate limit | 30 คำขอต่อ IP ต่อนาที เกินแล้วได้ `429` |
| ใบรับรอง | เป็น self-signed ใช้การตรวจด้วย certificate pin (ดูด้านล่าง) |

## การยืนยันตัวตนและสิทธิ์

แอปมี API key 3 ระดับ สร้างและดูได้ในหน้าหลักของแอป

| ระดับ | ทำได้ |
|---|---|
| **อ่านอย่างเดียว** (`READ`) | ดูสถานะ การตั้งค่า ข้อความ และผลการส่ง |
| **ส่งและลบ** (`SEND`) | ทุกอย่างของ `READ` + ส่ง SMS และลบข้อความที่จบแล้ว |
| **ผู้ดูแล** (`ADMIN`) | ทุกอย่างของ `READ` + ล้างข้อความที่จบแล้ว และตั้งค่าการเก็บข้อความ |

- key ที่ใช้ไม่ถูกต้อง ได้ `401 unauthorized`
- key ถูกต้องแต่สิทธิ์ไม่พอ ได้ `403 insufficient_scope`
- แต่ละ key อาจถูกจำกัดให้ใช้ได้จาก IP ที่กำหนดในแอป ถ้าไม่กำหนดจะใช้ได้จากทุกเครื่องใน LAN
- สิทธิ์ไม่ทับกันข้ามระดับ `ADMIN` ส่ง SMS หรือลบรายการไม่ได้ และ `SEND` ล้างข้อความหรือตั้งค่าการเก็บข้อความไม่ได้ ต้องใช้ key ที่ระดับตรงกัน

**สิ่งที่ทำผ่าน API ไม่ได้** ต้องทำที่โทรศัพท์เท่านั้น ได้แก่ ตั้งค่า webhook, กฎส่งต่อ, เปลี่ยนพอร์ต, สร้าง key ใหม่, เริ่มและหยุด gateway, ตั้งโควตาต่อวัน, เทมเพลต, การตั้งเวลาส่ง, การสำรองและกู้คืน

## Certificate pin

เซิร์ฟเวอร์ใช้ใบรับรองที่สร้างเองในเครื่อง ให้ตรวจด้วย public key pin ที่แสดงในแอป แทนการเชื่อใบรับรองทั่วไป

```bash
curl --pinnedpubkey 'sha256//<pin-จากแอป>' -k \
  -H "Authorization: Bearer <api-key>" \
  https://192.168.1.50:8443/v1/health
```

`-k` ปิดการตรวจ CA และชื่อโฮสต์ เพราะใบรับรองเป็น self-signed การตรวจจริงทำโดย `--pinnedpubkey`

## รูปแบบข้อผิดพลาด

ทุกข้อผิดพลาดตอบเป็น JSON ดังนี้

```json
{"error": "invalid_to"}
```

| HTTP | error | ความหมาย |
|---|---|---|
| 400 | `invalid_json`, `empty_body`, `invalid_to`, `invalid_message`, `message_too_long`, `missing_idempotency_key`, `invalid_idempotency_key`, `invalid_sim`, `invalid_id`, `invalid_kind`, `invalid_path`, `invalid_days`, `invalid_direction`, `chunked_not_supported` | ข้อมูลในคำขอไม่ถูกต้อง |
| 401 | `unauthorized` | key ไม่ถูกต้องหรือไม่ได้ส่ง |
| 403 | `forbidden` | เรียกจากนอก LAN |
| 403 | `ip_not_allowed` | IP ไม่อยู่ในรายการที่อนุญาตของ key นี้ |
| 403 | `insufficient_scope` | key ไม่มีสิทธิ์พอ |
| 404 | `not_found` | ไม่พบรายการ หรือไม่มี endpoint นี้ |
| 409 | `idempotency_key_reused` | key เดิมแต่เนื้อหาไม่ตรงกับครั้งแรก |
| 409 | `message_still_pending` | ลบข้อความขาออกที่ยังรอส่งไม่ได้ |
| 413 | `body_too_large` | body เกิน 8 KB |
| 429 | `rate_limited` | เรียกถี่เกินไป |
| 429 | `daily_limit_reached` | ถึงโควตาการส่งต่อวันแล้ว |
| 500 | `internal_error` | เกิดข้อผิดพลาดภายในเซิร์ฟเวอร์ |

## Endpoints

### ตรวจสอบ

#### `GET /v1/health` (สิทธิ์: อ่าน)

```json
{"ok": true}
```

#### `GET /v1/status` (สิทธิ์: อ่าน)

```json
{
  "running": true,
  "retention_days": 30,
  "webhook_configured": true,
  "pending_webhooks": 0,
  "sms_counts": {"queued": 2, "sending": 0, "sent": 15, "failed": 1}
}
```

- `running` บอกว่า gateway กำลังทำงานอยู่หรือไม่
- `sms_counts` นับงานขาออกตามสถานะ

#### `GET /v1/settings` (สิทธิ์: อ่าน)

```json
{"retention_days": 30}
```

### ข้อความ

#### `GET /v1/messages` (สิทธิ์: อ่าน)

| พารามิเตอร์ | ค่าเริ่มต้น | รายละเอียด |
|---|---|---|
| `direction` | `all` | `all`, `in` (รับเข้า) หรือ `out` (ส่งออก) |
| `limit` | `50` | 1 ถึง 200 ค่าที่เกินช่วงจะถูกปรับเข้าช่วง ค่าที่ไม่ใช่ตัวเลขใช้ค่าเริ่มต้น |
| `before` | ไม่มี | เวลาแบบ unix มิลลิวินาที เอาเฉพาะรายการที่เก่ากว่าเวลานี้ ใช้แบ่งหน้า |

ตัวอย่างการเรียก:

```bash
curl --pinnedpubkey 'sha256//<pin>' -k -H "Authorization: Bearer <key>" \
  "https://192.168.1.50:8443/v1/messages?direction=in&limit=20"
```

คำตอบ:

```json
{
  "messages": [
    {"kind": "in", "id": 12, "peer": "+66812345678", "body": "สวัสดี", "time": 1731230000000, "status": null, "sim": null},
    {"kind": "out", "id": 7, "peer": "+66899999999", "body": "ทดสอบ", "time": 1731229000000, "status": "SENT", "sim": 2}
  ],
  "next_before": 1731229000000
}
```

- รายการเรียงจากใหม่ไปเก่า
- `kind` เป็น `in` หรือ `out`
- `status` ของข้อความขาออกเป็น `QUEUED`, `SENDING`, `SENT`, `FAILED` หรือ `DELIVERED` โดย `DELIVERED` หมายถึงผู้ให้บริการรายงานว่าถึงผู้รับแล้ว (บางรายไม่รองรับ) สถานะนี้แสดงเฉพาะที่นี่ ส่วน `GET /v1/sms/{id}` ใช้ `status` เป็น `SENT` และดูการถึงผู้รับจาก `delivered_at` แทน
- ข้อความที่ซ่อนไว้ (ผู้ติดต่อที่ถูกบล็อก และข้อความที่ตรงคำสแปม) ไม่แสดงในรายการนี้
- `next_before` ใช้เป็นค่า `before` ของหน้าถัดไป เป็น `null` เมื่อไม่มีรายการ

#### `GET /v1/sms/{id}` (สิทธิ์: อ่าน)

ดูสถานะงานส่ง SMS รายการเดียว

```json
{
  "id": 7,
  "idempotency_key": "order-20261110-0001",
  "to": "+66899999999",
  "sim": 2,
  "status": "SENT",
  "attempts": 1,
  "last_error": null,
  "created_at": 1731229000000,
  "updated_at": 1731229100000,
  "delivered_at": null
}
```

สถานะที่เป็นไปได้: `QUEUED` (รอส่งหรือรอส่งซ้ำ), `SENDING`, `SENT`, `FAILED` (ไม่สำเร็จและจะไม่ส่งซ้ำแล้ว ดู `last_error`: `partial_send` = บางฉบับถึงระบบวิทยุแล้ว, `outcome_unknown` = ไม่ได้รับผลกลับจากระบบ, ค่าอื่น = ลองครบ 4 ครั้งแล้วยังไม่สำเร็จ)

การถึงผู้รับแสดงใน `delivered_at` (unix มิลลิวินาที) ซึ่งเป็น `null` ถ้ายังไม่ได้รับรายงาน หรือผู้ให้บริการไม่รองรับ สถานะยังเป็น `SENT` และ webhook `sms.delivered` แจ้งเหตุการณ์เดียวกัน

#### `DELETE /v1/messages/in/{id}` (สิทธิ์: ส่งและลบ)

ลบข้อความขาเข้ารายการนั้น ตอบ `{"deleted": true}` หรือ `404`

#### `DELETE /v1/messages/out/{id}` (สิทธิ์: ส่งและลบ)

ลบงานขาออกได้เฉพาะที่ส่งสำเร็จหรือไม่สำเร็จแล้ว

- ตอบ `{"deleted": true}`
- ถ้ายังรอส่งอยู่ได้ `409 message_still_pending`
- ถ้าไม่พบได้ `404`

#### `POST /v1/messages/clear-finished` (สิทธิ์: ผู้ดูแล)

ลบข้อความขาเข้าทั้งหมด และงานขาออกที่จบแล้วทั้งหมด งานที่ยังรอส่งจะไม่ถูกลบ

```json
{"deleted": 42}
```

### ส่ง SMS

#### `POST /v1/sms` (สิทธิ์: ส่งและลบ)

ต้องส่ง header `Idempotency-Key` ทุกครั้ง เป็นค่าที่ผู้เรียกกำหนดเองความยาว 8 ถึง 64 ตัวอักษร ใช้ได้เฉพาะ `A-Z a-z 0-9 _ -`

```bash
curl --pinnedpubkey 'sha256//<pin>' -k \
  -H "Authorization: Bearer <key>" \
  -H "Idempotency-Key: order-20261110-0001" \
  -H "Content-Type: application/json" \
  -d '{"to":"0812345678","message":"ทดสอบ","sim":2}' \
  https://192.168.1.50:8443/v1/sms
```

| ฟิลด์ | จำเป็น | รายละเอียด |
|---|---|---|
| `to` | ใช่ | เบอร์ปลายทาง รับได้หลายรูปแบบ เช่น `0812345678`, `021234567`, `0066812345678`, `66812345678`, `+66 81 234 5678` แล้วแปลงเป็น `+66...` |
| `message` | ใช่ | ไม่ว่างและไม่เกิน 1,000 ตัวอักษร (เกินได้ `400 invalid_message`) ส่งได้สูงสุดตามจำนวนฉบับที่ตั้งไว้ในแอป (1 ถึง 5 ฉบับ ค่าเริ่มต้น 5 เกินได้ `400 message_too_long`) ข้อความยาวจะถูกแบ่งเป็นหลายฉบับอัตโนมัติ ข้อความภาษาไทยหนึ่งฉบับรับได้ประมาณ 70 ตัวอักษร ข้อความภาษาอังกฤษประมาณ 160 ตัวอักษร |
| `sim` | ไม่ | `1` หรือ `2` ถ้าไม่ใส่หรือส่ง `null` จะใช้ซิมเริ่มต้นของเครื่อง ค่าอื่นได้ `400 invalid_sim` |

คำตอบ:

- `202 Accepted` เมื่อสร้างงานใหม่ เนื้อหาเป็นข้อมูลงาน ณ ตอนที่สร้าง (มักเป็น `QUEUED`) ดูสถานะล่าสุดได้ที่ `GET /v1/sms/{id}`
- `200 OK` เมื่อ `Idempotency-Key` เดิมและเนื้อหาเดิม จะคืนงานเดิม ไม่สร้างซ้ำ
- `409 idempotency_key_reused` เมื่อ key เดิมแต่เนื้อหาต่างไป

ระบบหยิบงานไปส่งทันทีหลังรับคำขอ โดยทั่วไปจึงเริ่มส่งทันที เว้นแต่มีงานค้างในคิวที่ต้องส่งก่อน

ข้อความหลายฉบับจะถือว่าสำเร็จเมื่อทุกฉบับส่งได้ ระบบไม่ส่งข้อความซ้ำเพื่อกันผู้รับได้รับซ้ำ: ถ้าไม่มีฉบับใดถูกรับเข้าระบบวิทยุเลย จะลองส่งใหม่อัตโนมัติ รวมครั้งแรกเป็น 4 ครั้ง ถ้าบางฉบับถูกรับไปแล้ว หรือไม่ได้รับผลกลับจากระบบ จะเป็น `FAILED` ทันทีโดยไม่ลองซ้ำ (ดู `last_error`)

โควตาต่อวันมีผลกับการส่งผ่าน API ด้วย คำขอที่ใช้ key เดิมซ้ำจะไม่นับเพิ่ม

### การตั้งค่า

#### `PUT /v1/settings/retention` (สิทธิ์: ผู้ดูแล)

```bash
curl --pinnedpubkey 'sha256//<pin>' -k -X PUT \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{"days": 7}' \
  https://192.168.1.50:8443/v1/settings/retention
```

ค่าที่รับได้คือ `7`, `30` หรือ `90` ตอบ `{"retention_days": 7}` ค่าอื่นได้ `400 invalid_days`

ข้อความ บันทึกการเรียก API และงานที่จบแล้วที่เก่ากว่าจำนวนวันนี้จะถูกลบอัตโนมัติ

## Webhook (ขาออกจากแอป)

ตั้งค่าได้ที่โทรศัพท์เท่านั้น ต้องเป็น `https://` และ secret ยาวอย่างน้อย 16 ตัวอักษร

แต่ละ event ส่งเป็น `POST` ด้วย JSON และมี header:

| header | ความหมาย |
|---|---|
| `X-Gateway-Timestamp` | เวลา unix หน่วยวินาที |
| `X-Gateway-Signature` | `sha256=` ตามด้วย HMAC-SHA256 ของ `<timestamp>.<body>` ด้วย secret |

ฝั่งรับควรตรวจว่า timestamp ไม่เกิน 5 นาที, เทียบลายเซ็นแบบ constant-time และเก็บ `id` ไว้กันประมวลผลซ้ำ ตัวอย่างครบอยู่ที่ `examples/webhook_receiver.py`

event ที่มี:

| `event` | ส่งเมื่อ | ฟิลด์หลัก |
|---|---|---|
| `sms.received` | มี SMS ขาเข้า | `from`, `body`, `received_at` |
| `sms.sent` | radio รับ SMS ไปแล้ว (ยังไม่รับรองว่าถึงผู้รับ) | `sms_id`, `idempotency_key`, `to`, `sim`, `status`, `attempts`, `error` (เป็น null), `delivered_at` (เป็น null), `updated_at` |
| `sms.failed` | ไม่สำเร็จและจะไม่ส่งซ้ำแล้ว (ดู `error`) | เหมือน `sms.sent` และมี `error` |
| `sms.delivered` | ผู้ให้บริการส่งรายงานว่าถึงผู้รับแล้ว (บางรายไม่รองรับ) | เหมือน `sms.sent` และมี `delivered_at` |
| `webhook.test` | กดทดสอบจากแอป | `sent_at` |

- ส่ง event เฉพาะสถานะสุดท้าย ไม่ส่งทุกครั้งที่ลองใหม่
- ข้อความจากผู้ติดต่อที่ถูกบล็อก และข้อความที่ตรงคำสแปม ไม่ส่ง `sms.received`
- ถ้าส่งไม่สำเร็จ จะลองใหม่สูงสุด 6 ครั้งรวมครั้งแรก แล้วทิ้ง event และแจ้งเตือนที่โทรศัพท์
- ระบบส่งไป `http://` ไม่ได้

ตัวอย่าง `sms.received`:

```json
{"event": "sms.received", "id": "3f2c...", "from": "+66812345678", "body": "รหัส 1234", "received_at": 1731230000000}
```

## ส่งต่อ SMS (กฎส่งต่อ)

ตั้งกฎได้ที่โทรศัพท์เท่านั้น ที่หน้า **ตั้งค่า → จัดการกฎส่งต่อ** แต่ละกฎส่งไปที่ **Telegram** หรือ **HTTP** กฎแยกจาก webhook ด้านบน ทั้ง URL และ secret ตั้งแยกกัน แต่ลงลายเซ็นด้วยวิธีเดียวกัน

### เมื่อไรระบบจะส่ง

- ส่งเฉพาะ SMS ขาเข้า กฎ SMS ต้องกรองอย่างน้อยหนึ่งอย่าง คือชื่อผู้ส่ง (ตรงทั้งหมด / มีคำนี้ / ขึ้นต้นด้วย) หรือเนื้อหา (มีคำนี้ ไม่สนตัวพิมพ์) ถ้ากรองหลายอย่างต้องตรงทุกเงื่อนไข กฎที่ไม่กรองเลยจะไม่ส่งอะไร
- ชื่อผู้ส่งที่เป็นเบอร์โทรใช้เทียบหลังแปลงรูปแบบ เช่น `0812345678`, `+66812345678` และ `0066812345678` ถือว่าเป็นเบอร์เดียวกัน
- ข้อความจากเบอร์ที่ถูกบล็อก และข้อความที่ตรงคำสแปมในแอป จะไม่ถูกส่งต่อ
- ข้อความเดิมจากผู้ส่งเดิมที่เข้ามาภายในช่วง ±60 วินาทีถือว่าเป็นข้อความเดียวกัน ประมวลผลเพียงครั้งเดียว (ไม่ส่งต่อ ไม่แจ้งเตือน และไม่ส่ง webhook ซ้ำ)
- ปลายทาง HTTP ต้องขึ้นต้นด้วย `https://` และ secret ยาวอย่างน้อย 16 ตัวอักษร
- ใบรับรองของปลายทางต้องออกโดย CA ที่ Android เชื่อถือ ใบรับรองแบบ self-signed จะส่งไม่สำเร็จ

### คำขอที่แอปส่งไปยังปลายทาง HTTP

`POST` ด้วย `Content-Type: application/json; charset=utf-8` และมี header:

| header | ความหมาย |
|---|---|
| `X-Gateway-Timestamp` | เวลา unix หน่วยวินาที |
| `X-Gateway-Signature` | `sha256=` ตามด้วย HMAC-SHA256 ของ `<timestamp>.<body>` ด้วย secret ของกฎ เป็นเลขฐานสิบหกตัวพิมพ์เล็ก |

- ลายเซ็นคำนวณจาก body ดิบทุกไบต์ที่ได้รับ ให้ตรวจก่อนแปลง JSON ลำดับ key ใน body อาจไม่ตรงกับตัวอย่างด้านล่าง ให้ใช้ body ที่ได้รับจริง
- ฝั่งรับควรตรวจ timestamp ไม่เกิน 5 นาที และเทียบลายเซ็นแบบ constant-time ตัวอย่างอยู่ที่ `examples/webhook_receiver.py`
- ตอบ `2xx` ถือว่าสำเร็จ คำตอบอื่น รวมถึง redirect (`3xx`) การหมดเวลา หรือเชื่อมต่อไม่ได้ ถือว่าไม่สำเร็จ แอปไม่ตาม redirect
- แอปรอการเชื่อมต่อและการอ่านคำตอบไม่เกิน 10 วินาที

### การลองส่งซ้ำ

- ถ้าไม่สำเร็จ แอปจะลองส่งซ้ำ รวมครั้งแรกทั้งหมด 6 ครั้ง โดยรอประมาณ 10, 20, 40, 80 และ 160 วินาทีก่อนแต่ละครั้ง (อาจนานกว่าเล็กน้อยตามการจัดตารางของระบบ)
- ลองครบแล้วยังไม่สำเร็จ แอปจะทิ้งงานนั้นและแจ้งเตือนที่โทรศัพท์ว่า "ส่งต่อ SMS ไม่สำเร็จ"
- การลองซ้ำส่ง body และ `id` เดิม ฝั่งรับควรกันประมวลผลซ้ำด้วย `id` และตอบ `2xx` กับรายการที่ซ้ำ เพื่อให้แอปหยุดส่ง
- ลำดับที่ข้อความถึงปลายทางไม่รับประกัน ให้เรียงด้วย `received_at`

### payload `sms.forwarded`

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `event` | string | ค่าคงที่ `sms.forwarded` |
| `id` | string | UUID ของงานส่งต่อ ใช้กันประมวลผลซ้ำ |
| `rule_id` | number | รหัสกฎที่ตรงเงื่อนไข ระหว่างทดสอบกฎที่ยังไม่บันทึกจะเป็น `0` |
| `from` | string | ผู้ส่งตามที่โทรศัพท์รับมา เช่นเบอร์โทรหรือชื่อผู้ส่ง |
| `body` | string | เนื้อหา SMS ทั้งข้อความ รวมทุกส่วนที่แยกมา |
| `received_at` | number | เวลาที่แอปประมวลผล หน่วยมิลลิวินาที |
| `test` | boolean | มีเฉพาะตอนกดปุ่มทดสอบในหน้ากฎ |

ตัวอย่างนี้ลงลายเซ็นด้วย secret `example-secret-0123456` และ timestamp `1731230000` ตรวจได้ด้วย `examples/webhook_receiver.py`

```http
POST /hook HTTP/1.1
Content-Type: application/json; charset=utf-8
X-Gateway-Timestamp: 1731230000
X-Gateway-Signature: sha256=0d821f723cffa86db75d9a95569067bced57730762f5754a760b5401e8cd2ed6

{"event":"sms.forwarded","id":"9b2f6c1e-4a7d-4e0b-8c52-1f3a7e9d0b11","rule_id":3,"from":"+66812345678","body":"รหัส OTP 1234","received_at":1731230000000}
```

ปุ่มทดสอบในหน้ากฎส่ง payload ที่มี `"test": true` ไปยังปลายทางครั้งเดียว ไม่เข้าคิวและไม่ลองซ้ำ

### ปลายทาง Telegram

Telegram ไม่ได้รับ JSON นี้ ข้อความจะขึ้นต้นด้วย `จาก <ผู้ส่ง>` บรรทัดแรก ตามด้วยเนื้อหา ตัดไม่เกิน 4000 ตัวอักษร การลองซ้ำและการแจ้งเตือนเมื่อทิ้งงานเหมือนปลายทาง HTTP

แจ้งเตือนจากแอปที่ส่งเข้า Telegram ขึ้นต้นด้วย `แจ้งเตือนจาก <ชื่อแอป>` บรรทัดแรก ตามด้วยหัวข้อและข้อความ (ถ้ามี) ตัดไม่เกิน 4000 ตัวอักษรเช่นกัน

### กฎแจ้งเตือนจากแอป (`notification.forwarded`)

กฎแจ้งเตือนต้องเลือกแอปอย่างน้อยหนึ่งแอป ไม่เลือกจะไม่ส่งอะไรเลย ถ้ากรอกคำ คำนั้นต้องมีในหัวข้อหรือข้อความ (ไม่สนตัวพิมพ์) จึงจะส่ง

กฎแจ้งเตือนที่ปลายทาง HTTP ส่ง event นี้ไปยัง URL ของกฎ ลงลายเซ็น ลองซ้ำ และตอบ `2xx` เหมือนกัน (ปลายทาง Telegram ดูหัวข้อด้านบน) ต่างกันที่ฟิลด์:

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `event` | string | ค่าคงที่ `notification.forwarded` |
| `id` | string | UUID ของงานส่งต่อ |
| `rule_id` | number | รหัสกฎที่ตรงเงื่อนไข |
| `app` | string | ชื่อ package ของแอปที่ส่งแจ้งเตือน |
| `app_name` | string | ชื่อแอปที่แสดงในเครื่อง |
| `title` | string | หัวข้อแจ้งเตือน อาจเป็นค่าว่าง |
| `text` | string | ข้อความแจ้งเตือน อาจเป็นค่าว่าง |
| `received_at` | number | เวลาที่แจ้งเตือนถูกโพสต์ หน่วยมิลลิวินาที |
| `test` | boolean | มีเฉพาะตอนกดปุ่มทดสอบในหน้ากฎ |

## ข้อควรรู้

- เนื้อหาข้อความและเบอร์โทรถูกเข้ารหัสในเครื่อง ถอดรหัสเฉพาะตอนอ่าน
- key ทุกระดับเห็นข้อความทั้งหมดใน `GET /v1/messages` ยกเว้นข้อความที่ซ่อนไว้ จึงควรแจกจ่าย key ให้เฉพาะระบบที่จำเป็น
- ข้อความที่ซ่อนไว้ไม่ส่ง webhook การส่งต่อ หรือการแจ้งเตือน และไม่ถูกบันทึกลงระบบ SMS ของเครื่อง
- ทุกการเรียกถูกบันทึกในบันทึกการเรียก API ของแอป (ดูได้ในแอป)
- ความล้มเหลวของการส่งจากผู้ให้บริการ เช่น สัญญาณหรือซิม จะแสดงใน `last_error`
