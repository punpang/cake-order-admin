# สถานะความปลอดภัย (ตรวจเมื่อ 2026-11-10)

ผลตรวจโค้ดทั้งระบบ (ฟังก์ชันเซิร์ฟเวอร์ ฐานข้อมูลจริง ฝั่งแอป หน้าจอ/การตั้งค่า) และสิ่งที่แก้แล้ว

## แก้แล้ว
- `sms-send`: อ่านกล่องข้อความเข้า/สถานะเกตเวย์ต้องมีสิทธิ์ `manage` · จำกัดส่ง 60 ครั้ง/ชม./คน · `active` ต้องเป็น true
- `customer-auth`: ส่ง OTP ผ่าน SMS Gateway v1 · เพดานขอ OTP รวม 120 ครั้ง/ชม. · ใช้ `cf-connecting-ip` แทน `x-forwarded-for` ตัวซ้ายสุด
- `order-link`: ตัดที่อยู่/แผนที่/รายละเอียดจัดส่ง/วันเกิด/หมายเหตุสินค้าและเบอร์เต็มที่เซิร์ฟเวอร์ · ไม่เขียนทับการเพิกถอนลิงก์
- ลิงก์ย่อ: ตรวจที่เซิร์ฟเวอร์ผ่าน RPC `punpang_resolve_short_link` · ปิดการอ่านตาราง `shortLinks` โดยผู้ไม่ล็อกอิน · **ห้ามเก็บโทเคนลิงก์ออร์เดอร์ (`/o/<token>`) ไว้ในปลายทางลิงก์ย่อ**
- RPC: `punpang_order_search` เรียกโดย anon ไม่ได้ · จองคูปองแบบอะตอมิก `punpang_claim_coupon` / `punpang_release_coupon`
- worker (R2): `/upload` และ `/delete` ตรวจสิทธิ์ตามชนิดไฟล์ (ตรงกับ storage policy)
- แอป: `/ADMIN/...` ไม่ข้ามหน้าล็อกอิน · `public/_headers` (nosniff, referrer, frame-ancestors, CSP แบบ Report-Only) · `package-lock.json` · ลิงก์หน้าร้านรับเฉพาะ http(s)
- เงิน: ปัดยอดเป็นสตางค์ · ตรวจจำนวนเงินแจ้ง/ยืนยันชำระ · เพดานส่วนลด (แต้ม คูปอง ปรับราคา POS) · คืนสต็อก POS ตามที่ตัดจริง
- sync: แก้ไขระหว่างกำลังบันทึกไม่หายเงียบ · ไม่ค้างเมื่อ push พัง · เขียนออร์เดอร์/ลูกค้าแบบเทียบเวอร์ชัน ไม่เขียนทับข้อมูลที่ถูกแก้ที่อื่นก่อน

## ยังเหลือ (ต้องตัดสินใจ/ทดสอบก่อน)
- **บอท AI (ยังไม่ deploy):** คีย์ `ANTHROPIC_API_KEY` ต้องเป็น Supabase secret เท่านั้น (ตั้งผ่านฟอร์มที่ปลอดภัย ห้ามวางในแชท/โค้ด/log) · ส่งให้โมเดลเฉพาะข้อความปัจจุบันของลูกค้า (ไม่มีประวัติแชท/ชื่อ/ข้อความพนักงาน) และข้อมูลร้าน/สินค้าสาธารณะ · ข้อความที่ `scrubPII` พบเบอร์/อีเมล/เลขออร์เดอร์/เลขยาว หรือมีชื่อลูกค้า จะไม่ส่งเลย · การจับชื่อที่ลูกค้าพิมพ์เองโดยไม่รู้จักชื่อไม่ได้ 100% จึงยังมีความเสี่ยงเล็กน้อย · เพดานต่อวันกันค่าใช้จ่ายเกิน · aiLog เก็บข้อความลูกค้าตัด 200 ตัวอักษร (ต้องกำหนดอายุข้อมูลตามนโยบาย PDPA) · migration `punpang_ai_take` ยังไม่ได้ apply
- **CSP**: เปลี่ยน `Content-Security-Policy-Report-Only` เป็น `Content-Security-Policy` ใน `public/_headers` หลังดู Console ว่าไม่มีรายการถูกบล็อกที่ต้องใช้
- **Leaked Password Protection**: เปิดเองที่ Supabase Dashboard → Authentication → Providers → Email
- **แต้มสะสม**: ตัดแต้มยังทำฝั่งแอป (ป้องกันการเขียนทับด้วยเทียบเวอร์ชันแล้ว) · ทางที่ถูกคือตารางรายการแต้มแบบเพิ่มอย่างเดียว ให้เซิร์ฟเวอร์คิดยอดคงเหลือ
- **`fb-webhook` / `fb-send` / `fb-connect`** (กระทบทุกข้อความของเพจ ต้องทดสอบกับบัญชี Messenger ทดสอบก่อน deploy):
  - ตอบ Meta ก่อนดาวน์โหลดไฟล์แนบ (ตอนนี้ดาวน์โหลดก่อนตอบ เสี่ยง Meta ส่งซ้ำ)
  - จำกัดโดเมนไฟล์แนบ (`*.fbcdn.net`, `*.fbsbx.com`) และไม่ตามรีไดเรกต์
  - `fb-send`: จำกัดโดเมนลิงก์การ์ด (ต้องรู้โดเมนใช้งานจริงก่อน), rate limit ต่อคน, กันส่งซ้ำ
  - `fb-connect`: ลบ page token ค้างหลัง OAuth ไม่สำเร็จ
- **สิทธิ์เขียนคอลเลกชัน `consents`/`outbox`** ใน `punpang_rec_can` ยังเปิดให้พนักงานทุกคน (`outbox` จำเป็นต่อการแจ้งเตือนจากทุกบทบาท) ต้องไล่ดูทีละบทบาทก่อนจำกัด
- `punpang_click_pairs` / `punpang_record_click` เรียกโดย anon ได้ตามการออกแบบ (คำนวณรูปแนะนำ) ข้อมูลเป็นแฮช
- สคีมาพื้นฐาน (ตาราง RLS storage policy) และ `config.toml` (`verify_jwt`) ยังไม่อยู่ในรีโป
