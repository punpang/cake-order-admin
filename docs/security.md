# สถานะความปลอดภัย

ผลตรวจโค้ดทั้งระบบ (ฟังก์ชันเซิร์ฟเวอร์ ฐานข้อมูลจริง ฝั่งแอป หน้าจอ/การตั้งค่า) และสิ่งที่แก้แล้ว · รอบล่าสุด 2026-11-14 อยู่ด้านบน รอบ 2026-11-10 อยู่ถัดลงไป

## รอบแก้ 2026-11-15 (ต่อจากผลตรวจ main `0e38009`) — แก้ในรีโปแล้ว ยังไม่ได้ deploy

**ผลตรวจซ้ำด้วยการรันจริง:** `supabase/tests/run.sh` บน Postgres 16 ผ่าน 73 migration และ 83 ข้อ · Deno ผ่าน 278 + 10 ข้อ และ `deno check` ทุก Edge Function · `npm test` ผ่าน 25 ไฟล์ · `npm run build` ผ่าน
**ยังไม่ได้รันบน production** — ทุกอย่างด้านล่างทดสอบกับฐานจำลองที่ประกอบจาก migration ของรีโป

**ลำดับ deploy (ทำเอง · ห้ามสลับลำดับ):**
1. ตั้งความลับ 2 ที่ให้ค่าเดียวกัน: Edge secret `PUSH_SEND_KEY` และ Vault `push_send_key` (ค่าสุ่มยาว เช่น `openssl rand -hex 32`) — ตั้งก่อน deploy `push-send` ไม่เช่นนั้นแจ้งเตือนจะหยุด (ฟังก์ชันปฏิเสธคำขอที่ไม่มีคีย์)
2. รัน SQL ตามลำดับชื่อไฟล์: `20261115000000` (ถ้ายังไม่รัน) → `20261115020000` → `20261115030000` → `20261115040000` (รันซ้ำได้ปลอดภัย)
3. Deploy Edge Function `push-send`
4. Deploy Worker `punpang-files` (ลบสลิป และอ่านรูปอ้างอิงทุกหน้า)
5. Deploy หน้าเว็บ (`src/data/store.js`, `src/views/account/AccountChat.vue`) และ build แอป Android ใหม่ (`CustomerDisplayPlugin`)
6. ทดสอบในเบราว์เซอร์: เปลี่ยนผู้ซื้อของออร์เดอร์ที่มีคะแนน · แก้ราคา/ส่วนลดในออร์เดอร์ร่างและออร์เดอร์ที่กำลังเตรียม · แนบสลิป · รับแจ้งเตือนพนักงาน

**ช่องโหว่ที่ปิดในรอบนี้ (พร้อมผลทดสอบ):**
- คืนเงินเป็นคะแนนซ้ำหลังลูกค้าใช้คะแนนไปแล้ว (เดิมชำระ 1,000 บาทได้ส่วนลดรวม 2,000 บาท) → เพดานสะสมต่อออร์เดอร์ที่ตาราง `punpang_order_issued` ทดสอบ: ปฏิเสธ `cap_exceeded`
- ออกคะแนนให้ลูกค้าคนอื่นจากออร์เดอร์ของคนหนึ่ง (เดิมออร์เดอร์ 1,000 บาทออกได้ 2,000 แต้ม) → คืนเงินต้องเป็นผู้ซื้อของออร์เดอร์ (`order_customer_mismatch`)
- สิทธิ์หมุนเพิ่มซ้ำจากออร์เดอร์เดิม (เดิมเรียก 3 ครั้งได้ 15 สิทธิ์จากออร์เดอร์ 5 สิทธิ์) → โอนได้เฉพาะที่ตัดจากผู้ซื้อเดิมไว้ (`pending_*`) โอนซ้ำไม่เพิ่มของ
- ผู้ใช้แอปแก้ราคา/จำนวนรายการ ส่วนลด ค่าส่ง VAT ยอดงวดที่ชำระ ผู้ซื้อ คะแนนและคูปองที่ใช้ของออร์เดอร์ใดก็ได้ (เอกสารเดิมบรรทัด 34 ระบุว่า "ของตัวเอง" ซึ่งแคบเกินจริง) → trigger `punpang_orders_field_guard` ตรวจรายฟิลด์ตามสิทธิ์ ทดสอบ: ช่างเค้กแก้ราคาไม่ได้ · ร่างแก้ได้ · ยอดงวดที่ยืนยันแก้ไม่ได้ถ้าไม่มีสิทธิ์
- ผู้ไม่ล็อกอิน (anon) มีสิทธิ์ ALL บนตารางคลิก/push/tungngern (แม้ RLS กันแถวไว้) → เหลือ select 3 ตาราง (สินค้า ตั้งค่า รีวิว) และ RPC 4 ตัวที่หน้าร้านใช้ · ถอน TRUNCATE/REFERENCES/TRIGGER จากทุกตารางของ anon/authenticated
- Worker `/delete` ให้ผู้แจ้งชำระลบสลิปของออร์เดอร์ใดก็ได้ (ขัดกับกติกาข้อ 20 และ 53 ด้านล่าง) → ลบสลิปได้เฉพาะ `confirmPayment`/แอดมิน ทดสอบด้วย Deno
- `push-send` รับคำขอจากใครก็ได้ → ต้องมีหัว `x-push-key` ตรงกับคีย์ใน Vault (ไม่ตั้งคีย์ = ปิดทั้งหมด) ทดสอบด้วย `pushauth.test.ts`
- Worker อ่านรูปอ้างอิงได้แค่ 1,000 แถวแรกต่อตาราง (รูปที่ถูกอ้างในแถวที่ 1,001+ ถูกนับว่าไม่ถูกใช้และย้ายเข้าถังขยะได้) → อ่านทุกหน้า และหยุดลบถ้าอ่านไม่สำเร็จ ทดสอบด้วย Deno
- ตัวนับคลิกรูปเค้ก นับทั้งตารางทุกครั้งที่มีคนกด → ใช้สถิติของตาราง
- การตรวจเลขอ้างอิงการชำระซ้ำ (`data @> …`) สแกนทุกออร์เดอร์ → ดัชนี GIN
- FK `punpang_push_devices.staff_id` ไม่มีดัชนี → เพิ่มแล้ว
- Android: จอลูกค้าตรวจว่าเป็น JSON ก่อนส่งเข้า WebView และ escape สตริง · แชทลูกค้า: ลิงก์รูปผ่าน `safeHref`

**ผลวัดความเร็ว (ฐานจำลอง 50,000 ออร์เดอร์ / 49,000 คลิก · วัดด้วย `clock_timestamp`):**
- ค้นเลขอ้างอิงการชำระ: ค่ากลาง 16.0 ms → 1.5 ms
- บันทึกการคลิก 1 ครั้ง: เฉลี่ย 1.83 ms → 0.027 ms

**ข้อควรรู้ที่พบระหว่างทำ:**
- การเปลี่ยนผู้ซื้อในแอปเรียก `cut` แล้ว `earn` ด้วย `points: l.points` เต็มก้อน แม้คะแนนบางส่วนถูกใช้ไปแล้ว → เดิมสร้างคะแนนส่วนเกินได้ ตอนนี้โอนได้เท่าที่ตัดจริงเท่านั้น
- ตัวแปร `ord` ชนกับชื่อคอลัมน์ในไฟล์ hardening ที่ยังไม่รัน (ทำให้การตัด/คืนคะแนนล้มเหลว) — แก้แล้วก่อน deploy เวอร์ชันที่รันอยู่ไม่มีบั๊กนี้
- เวอร์ชันของ `punpang_ledger_apply` ที่รันอยู่ (20261110174623) มีช่องเดียวกับข้อ 1–3 ของรอบนี้ → ควรรันไฟล์ใหม่โดยเร็ว

**ยังเหลือ (ต้องตัดสินใจหรือทำต่อ):**
- ส่วนลดคูปอง (`couponsUsed`) ยังคำนวณจากแอป ยังไม่ตรวจกับคูปองที่ใช้จริงที่เซิร์ฟเวอร์ (ต้องมี RPC)
- ยืนยันสลิปอัตโนมัติ (ปิดเป็นค่าเริ่มต้น): ยืนยันจากภาพ OCR ที่ลูกค้าส่งเอง ยังไม่ตรวจกับธนาคาร — ควรตรวจก่อนเปิดใช้
- การเปลี่ยนผู้ซื้อยังเรียกจากแอป ระบบจำกัดยอดที่โอนได้ แต่ยังไม่บังคับว่าผู้ซื้อของออร์เดอร์เปลี่ยนจริงในธุรกรรมเดียวกัน
- ผู้มีสิทธิ์สร้างออร์เดอร์ยังแก้ข้อมูลลูกค้าได้ตามสิทธิ์เดิม (เช่น เบอร์โทร) — ไม่กระทบการเข้าสู่ระบบของลูกค้า
- การนับคลิกเป็นค่าประมาณจากสถิติของ Postgres (autovacuum ปรับให้เอง)
- Supabase ให้สิทธิ์เริ่มต้นกับ anon/authenticated ทุกฟังก์ชันใหม่ — migration ถัดไปต้องถอนสิทธิ์เองเสมอ
- ดัชนี GIN ถูกสร้างในไฟล์ migration (บล็อกการเขียนชั่วคราว) — ตารางออร์เดอร์ตอนนี้เล็ก หากโตมากควรสร้างแบบ `CONCURRENTLY` นอก migration
- ลดสิทธิ์ของพนักงานขายชั่วคราว (เช่น ถอน `changeBuyer`/`useLoyalty`) ก่อนรันไฟล์ใหม่ เป็นการตัดสินใจทางธุรกิจ ไม่ได้ทำในโค้ด

**Edge Function:**
- `customer-auth`: จองครั้งที่ลองผิดของ PIN/OTP ก่อนตรวจรหัส (เขียนแบบมีเงื่อนไข `_shared/authguard.ts`) · เดิมยิงคำขอพร้อมกันหลายร้อยคำขอเดา PIN/OTP ได้เกินเพดาน 5 ครั้งหลายเท่า · ล็อกบัญชีตั้งพร้อมการจองครั้งสุดท้าย · บันทึกโปรไฟล์เทียบ `updated_at` ไม่เขียนทับแต้มที่เพิ่งเปลี่ยน
- `customer-order`: ตัวจำกัดอัตราแบบใหม่ (`_shared/ratelimit.ts`) นับเฉพาะคำขอที่ผ่าน (เดิมนับคำขอที่ถูกปฏิเสธด้วย หน้าแชทที่โพลล์ทุก 3 วินาทีจึงถูกล็อกจนปิดหน้า) · ใช้ IP จาก `cf-connecting-ip` (ค่าซ้ายสุดของ `x-forwarded-for` ผู้เรียกปลอมได้) · เพิ่มเพดานต่อลูกค้า (อ่านแชท 40 ครั้ง/นาที · ลงทะเบียนแจ้งเตือน 10 ครั้ง/10 นาที) และต่อออร์เดอร์ (อ่านสลิป 12 ครั้ง/ชม.)
- เพดานเรียกโมเดลอ่านสลิป (`slipstore.ts`, `slipjob.ts`): ทั้งร้าน 300 ครั้ง/ชม. และต่อแชท 30 ครั้ง/24 ชม. · เกินแล้วไม่เรียกโมเดล สลิปยังเก็บให้พนักงานตรวจเอง (กันสลิป QR ปลอมที่รูปแบบถูกเผาค่า AI)
- `tungngern-receiver`: `received_at` ที่ไม่ใช่เวลาที่ถูกต้องไม่ทำให้ตอบ 500 (บันทึกด้วยเวลาปัจจุบัน ไม่จับคู่งวดชำระ)

**Worker `punpang-files`:** `/sign` ตรวจสิทธิ์ตามประเภทไฟล์นอกออร์เดอร์ (`webchat/` → `chat` · `manual/`, `pay-qr/` → `chat`/`reportPayment`/`confirmPayment` · `train/` → `manage`) เดิมพนักงาน active ทุกคนขอลิงก์ดูได้ทุกคีย์ · ส่ง `X-Content-Type-Options: nosniff` · path เข้ารหัสเสียตอบ 403/404 ไม่ใช่ 500 · `wrangler.jsonc` ไม่มี `SUPABASE_ANON_KEY` ตัวอย่างที่ทับค่าจริงตอน deploy

**แอป/อื่น ๆ:** ปิด `allowBackup` ใน Android (โทเค็นเซสชันในที่เก็บของ WebView ไม่ถูกสำรอง/ดึงด้วย `adb backup`) · แชทลูกค้าโพลล์แบบปรับความถี่ (3→15 วินาที หยุดเมื่อแท็บซ่อน ถอยเมื่อโดนจำกัด) · ลิงก์ไฟล์แนบในแชทผ่าน `safeHref` · CI (`.github/workflows/ci.yml`) รันเทสต์ Node/Deno/Postgres ทุก push/PR

- แอป: `/ADMIN/...` ไม่ข้ามหน้าล็อกอิน · `public/_headers` (nosniff, referrer, frame-ancestors + X-Frame-Options, HSTS 1 ปี, Cross-Origin-Opener-Policy, CSP แบบ Report-Only) · `package-lock.json` · ลิงก์หน้าร้านรับเฉพาะ http(s) ทั้งตอนบันทึก (`webUrl`/`checkMapUrl`) และตอนแสดงผล (`lib/safeUrl.js` `safeHref`) · ฟอนต์ฝังมากับเว็บ (`src/fonts.css`) ไม่เรียก Google Fonts จึงไม่ส่ง IP/ผู้อ้างอิงของผู้เข้าชมให้บุคคลที่สาม

- sync: แก้ไขระหว่างกำลังบันทึกไม่หายเงียบ · ไม่ค้างเมื่อ push พัง · เขียนออร์เดอร์/ลูกค้าแบบเทียบเวอร์ชัน ไม่เขียนทับข้อมูลที่ถูกแก้ที่อื่นก่อน
