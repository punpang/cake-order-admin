# หน้าออร์เดอร์ของลูกค้า + ชำระเงินเอง (รอบ G)

- หน้าเดียวกัน 2 ทาง: ลิงก์ `#/o/<token>` (ไม่ต้องล็อกอิน) และ `#/account/orders/<id>` (ล็อกอินเป็นเจ้าของ) ใช้คอมโพเนนต์ `CustomerOrderView` และข้อมูลชุดเดียว (`publicOrderView`) · ลิงก์ปิดบางส่วนเบอร์ ไม่แสดงที่อยู่/url/รายละเอียดจัดส่ง · ไม่มีต้นทุน/กำไร/โน้ตภายใน/ประวัติภายใน
- แถบขั้นตอน: รอชำระ → ยืนยันแล้ว → กำลังเตรียม → พร้อมรับ/ส่ง → ส่งมอบแล้ว · แจ้งเตือน: เกินกำหนดชำระ / รอร้านตรวจสลิป / ยืนยันแบบยังไม่ชำระ
- ชำระเงิน (ไม่ต้องรอร้านแจ้งยอด): เลือกยอด (ค้างทั้งหมด / ตามที่ร้านแจ้ง / ระบุเอง ≤ คงค้างที่ไม่ได้รอตรวจ) → QR พร้อมเพย์ตามยอด + เลขบัญชี → แนบสลิป (ย่ออัตโนมัติในเบราว์เซอร์ เหลือด้านยาว ≤1000px และ ≤ 2 MB) → ร้านตรวจและกดยืนยันเหมือนเดิม (ไม่ตัดอัตโนมัติ)
- ลูกค้าแจ้งชำระได้ ≤ 5 ครั้ง/ชม./ออร์เดอร์ · เลยกำหนดชำระ = แจ้งชำระไม่ได้ ต้องกด "ขอขยายเวลา" ให้ร้านอนุมัติ
- ตั้งค่า: ตั้งค่าร้าน → ช่องทางรับชำระ (พร้อมเพย์ / ชื่อบัญชี / ธนาคาร / เลขบัญชี) · QR สร้างในเบราว์เซอร์จาก payload EMVCo (`src/lib/promptpay.js`, ไลบรารี `qrcode`)
- โหมดจำลอง: ข้อมูล/สลิปอยู่ในหน่วยความจำของเบราว์เซอร์นี้ ลูกค้าข้ามเครื่องใช้ไม่ได้จนกว่าต่อ Supabase

## รูปงานเสร็จ + ขอไม่ให้ใช้รูปเผยแพร่ (รอบ T)

- พนักงาน (สิทธิ์ `workPhoto`) อัปโหลดรูปงานเสร็จในการ์ดสินค้าของออร์เดอร์ (เค้กสั่งทำและสินค้าสำเร็จ · ไม่รวมบิล POS) → ลูกค้าเห็นในหน้าออร์เดอร์ (ลิงก์/ล็อกอิน) + ข้อความแจ้งพร้อมลิงก์ (`photo_ready` มีช่องติ๊กแจ้งลูกค้า ค่าเริ่มต้นส่ง) · ระบบข้อความ/แชทส่งรูปไม่ได้ จึงส่งเป็นลิงก์
- หน้าออร์เดอร์ลูกค้าแสดงข้อความชี้แจงว่าร้านอาจนำรูปไปใช้เป็นรูปตัวอย่างบนเว็บ/โซเชียล (ทุกช่องทาง) และมีปุ่ม "ไม่อนุญาตให้ใช้รูปเผยแพร่" (ทั้งลิงก์และล็อกอิน)
- ขอแล้ว = รอร้านตรวจสอบ ระหว่างรอรูปถูกซ่อนจากเว็บทันที · ร้านอนุมัติ (หน้า จัดการ → คำขอไม่เผยแพร่รูป) = ลบรูปงานของออร์เดอร์นั้นทุกที่ (ออร์เดอร์ คลังรูป รูปสินค้า) + ห้ามอัปโหลดรูปใหม่ · ไม่อนุมัติ (ต้องมีเหตุผล) = กลับมาแสดงตามเดิม · ลูกค้ายกเลิกคำขอเองได้ขณะรอ · ร้านเปิดสิทธิ์ให้ใช้รูปได้อีกถ้าลูกค้าเปลี่ยนใจ · ลบข้อมูลลูกค้า (PDPA) ล้างรูปงานที่ผูกไว้ด้วย
