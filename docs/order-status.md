# สถานะออร์เดอร์ & กำหนดชำระ (รอบ F)

ลำดับ: ร่าง → รอชำระ → แจ้งยอดแล้ว → (ยืนยันชำระ | ยืนยันการสั่งซื้อ) → กำลังเตรียม → เตรียมสินค้าแล้ว → ส่งมอบแล้ว (ยกเลิกได้ก่อนส่งมอบ)

- **ยืนยันการสั่งซื้อ (ยังไม่ชำระ)**: ใช้เมื่อยังไม่มียอดชำระ แอดมินกดยืนยันตรงได้ พนักงานขายต้อง "ขออนุมัติ" ให้แอดมินอนุมัติ/ไม่อนุมัติ · ส่งมอบยังต้องคงค้าง = 0
- **กำหนดชำระ**: ตอนแจ้งยอดเลือก 15 นาที / 30 นาที / 1 ชม. / 3 ชม. / 24 ชม. / ไม่กำหนด / กำหนดเอง (ค่าเริ่มต้นตั้งที่ ตั้งค่าร้าน → กำหนดชำระเริ่มต้น) · ตัวแปรข้อความ `{ชำระก่อน}` `{ลิงก์ออร์เดอร์}`
- **เลยกำหนด**: ไม่ยกเลิกอัตโนมัติ · แจ้งทีม (Telegram, ครั้งเดียว) · ป้าย "เกินกำหนดชำระ" ในรายการ/รายละเอียด/แชท/บัญชีลูกค้า · ลูกค้าต้องขอขยายเวลา → พนักงานขยายหรือไม่อนุมัติ
- โหมดจำลอง: ข้อมูลอยู่ในหน่วยความจำของเบราว์เซอร์

## กำหนดชำระ — ตัวเลือกตามเวลานัด (รอบ F2)
- ทุกงวดที่แจ้งต้องมีกำหนดชำระ (ไม่มีปุ่ม "ไม่กำหนด") · ถ้าไม่ส่งมา ระบบเติม `ตอนนี้ + กำหนดชำระเริ่มต้น`
- ปุ่ม "ก่อนเวลานัด" (1/3/6/12/24 ชม. หรือกรอกเอง) และ "ล่วงหน้า N วัน ก่อน HH:mm" (ค่าเริ่มต้น 1 วัน 12:00) · ถ้าเวลาที่คำนวณผ่านไปแล้ว ปุ่มจะถูกปิดพร้อมเหตุผล
- เตือนลูกค้า (event `payment_reminder`) ครั้งเดียว ตั้งแต่ 09:00 (ตั้งค่าร้านปรับได้) เมื่อออร์เดอร์เป็นของพรุ่งนี้ + เคยแจ้งชำระ + ยังไม่ชำระเลย (ไม่ส่งถ้าลูกค้าแนบสลิปแล้ว หรือยืนยันแบบยังไม่ชำระ)
- การตรวจแจ้งเตือนตามเวลา: ถ้า config/scheduled.server = true เซิร์ฟเวอร์ (Edge Function scheduled ทุก 15 นาที) ส่งทั้งลูกค้าและทีม · ค่าเริ่มต้น (false) แอปเรียกตรวจทุก 60 วินาทีขณะเปิดหน้าเว็บ (โหมดสำรอง) · การลบคูปองหมดอายุและแจ้งเตือนบัญชียังทำในแอป

## ขั้นจัดส่ง (ออร์เดอร์ที่ส่งถึงที่)

เตรียมสินค้าแล้ว → **พร้อมจัดส่ง** → **กำลังจัดส่ง** (แจ้งลูกค้า) → ส่งมอบแล้ว · ข้ามขั้นไม่ได้ · รับที่ร้านใช้ เตรียมสินค้าแล้ว → ส่งมอบแล้ว เหมือนเดิม · คนส่งเห็นออร์เดอร์จัดส่งในขั้นเหล่านี้ · ส่งมอบต้องชำระครบ (ใช้ "รับชำระทันที" ที่หน้าออร์เดอร์ได้โดยไม่ต้องแจ้งยอด/กำหนดชำระ — สิทธิ์ยืนยันชำระ)

## ย้อนสถานะ (รอบ S)

- ปุ่ม "ย้อนสถานะ" ในหน้าออร์เดอร์ ย้อนทีละขั้นตามลำดับ (สิทธิ์ `revertStatus` ค่าตั้งต้นแอดมิน ติ๊กให้คนอื่นได้ที่ ผู้ใช้ & สิทธิ์) ต้องใส่เหตุผล · บันทึกประวัติ · ไม่ส่งข้อความถึงลูกค้า
- ผลข้างเคียง: ส่งมอบ→กลับ ถอนคะแนน/สิทธิ์หมุนที่ให้ + บัญชีกลับรายการรายได้ (คิดจากสถานะอัตโนมัติ) · ยืนยันชำระ→กลับ ยกเลิกยอดที่ยืนยันล่าสุด · แจ้งยอดแล้ว→กลับ ยกเลิกยอดที่แจ้ง · ยกเลิก→กลับ ได้เฉพาะไม่มีเงินคืน/ไม่ใช้คะแนน-คูปอง/ไม่ได้ยกเลิกหลังส่งมอบ
- ห้ามย้อน: บิล POS (ใช้ยกเลิกบิล) · รายการบัญชีของขั้นนั้นอยู่ในงวดที่ปิดแล้ว · เดือนภาษี VAT ยื่นแล้ว · มีใบกำกับภาษีใช้งานอยู่ (ยกเลิกใบก่อน)

## ติ๊กแจ้งลูกค้า

ทุกจุดที่ระบบส่งข้อความถึงลูกค้า (สร้าง/ส่งไปรอชำระ, แจ้งยอด, ยืนยัน/รับชำระ, ยืนยันสั่งซื้อ, เตรียมเสร็จ, ออกจัดส่ง, ส่งมอบ, ยกเลิก, แก้/ยกเลิกยอดที่แจ้ง, ยกเลิกยอดที่ยืนยัน, ผลขยายเวลาชำระ, เพิ่ม/ลบ/แก้รายการสินค้า, ปรับราคา, เริ่มเตรียม, พร้อมจัดส่ง, ใช้/ยกเลิกการใช้คะแนน) มีช่อง "แจ้งลูกค้า" ค่าเริ่มต้นติ๊ก · ไม่ติ๊ก = ไม่ส่งลูกค้า (ทีม/Telegram ยังได้รับ) และบันทึกในคิวข้อความเป็น "ข้าม" · ตัวเตือนตามเวลาปิดได้ที่ตั้งค่าแจ้งเตือนรายเหตุการณ์
