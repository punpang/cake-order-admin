# สั่งล่วงหน้า: วันชำระสุดท้ายแสดงต่อลูกค้า และจำกัดการขยายเวลา — Design

วันที่: 2026-11-25 · สถานะ: รอการอนุมัติ

## 1. เจตนา (Intent)
แคมเปญมี "วันชำระสุดท้าย" แต่ตอนนี้ (ก) ลูกค้าไม่เห็นวันนี้ที่หน้าสั่งซื้อ และ (ข) ร้านขยายเวลาชำระของออเดอร์เกินวันนั้นได้ ทำให้กติกาที่ระบบใช้ตอนรับออเดอร์ขัดกับการขยายเวลา ต้องการให้ทั้งสองอย่างตรงกัน: ลูกค้าเห็นวันจริง และร้านขยายได้ไม่เกินวันนั้น

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ต้องไม่เกิด
- **เป้าหมาย:** ลูกค้าเห็นวันชำระสุดท้ายของแคมเปญก่อนสั่ง · การขยายเวลาทุกครั้งต้องไม่เกินสิ้นวันชำระสุดท้ายตามเวลาไทย
- **ไม่ใช่เป้าหมาย:** เปลี่ยนวิธีคิดมัดจำ ค่าส่ง หรือบัญชี · เปลี่ยนการ reserve โควตา
- **ต้องไม่เกิด:** ออเดอร์ที่มี `payDueAt` เกินสิ้นวันชำระสุดท้ายของแคมเปญ · ลูกค้าเห็นวันผิดจากที่ระบบใช้จริง

## 3. ข้อจำกัด (Constraints)
- การตรวจวันต้องอยู่ที่เซิร์ฟเวอร์ (ฐานข้อมูล) ไม่เชื่อค่าจาก client
- วันสิ้นสุดคิดตามโซนเวลาไทย `T23:59:59.999+07:00` เหมือน `payDueAtOf` เดิม
- ออเดอร์ที่ขยายไปแล้วก่อนแก้ไข ไม่ถูกย้อนหลัง

## 4. แนวทาง (Approaches)
| ทาง | แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A (เลือก)** | ฐานข้อมูล `punpang_preorder_extend` ปฏิเสธ `p_new_due` ที่เกินสิ้นวันชำระสุดท้าย + ฝั่งลูกค้าแสดงวัน | บังคับที่จุดเดียว ตรงกับระบบ | ต้อง migration ใหม่และ Release |
| B | ตรวจเฉพาะหน้าร้าน (client) | ไม่ต้องแก้ฐานข้อมูล | client ข้ามได้ ไม่ปลอดภัย |
| C | ฐานข้อมูลตัดค่าให้เท่าวันสุดท้ายแทนการปฏิเสธ | ไม่มีข้อผิดพลาดให้ร้าน | ร้านไม่รู้ว่าค่าถูกเปลี่ยน |

**เลือก A** เพราะบังคับจริงและแจ้งผลชัด (ทาง C ซ่อนการเปลี่ยนค่า)

## 5. การออกแบบ (How)
- **ฐานข้อมูล:** migration ใหม่ สร้างฟังก์ชัน `punpang_preorder_extend` ทับของเดิม เพิ่มการตรวจ: ถ้าแคมเปญมี `data->>'payLastDate'` และ `p_new_due` มากกว่า `(payLastDate || 'T23:59:59.999+07:00')` ให้คืน error `past_last` (ไม่แตะข้อมูลอื่น) · คง grant เดิม (service_role เท่านั้น)
- **Edge Function `preorder-admin`:** action `extend` แปลง error `past_last` เป็นข้อความไทย "ขยายเวลาเกินวันชำระสุดท้ายของแคมเปญไม่ได้"
- **หน้าร้าน (`PreorderOrdersPanel.vue`):** แสดงข้อความ error นั้นในแถวออเดอร์ (ไม่เพิ่มการตรวจฝั่ง client)
- **หน้าลูกค้า (`StorePreorder.vue`):** การ์ดแคมเปญแสดง "วันชำระสุดท้าย: <วันที่ไทย>" เมื่อมีค่า (ข้อมูลนี้มาจากคำตอบ `campaigns` อยู่แล้ว)
- **ไม่เปลี่ยน:** `payDueAtOf` และการตรวจตอนสร้างออเดอร์

## 6. การตัดสินใจที่ผมเลือกเอง (แก้ได้)
- ข้อความลูกค้า: "วันชำระสุดท้าย" ตามคำที่คุณใช้ในหน้าตั้งค่า
- ไม่มี `max` ใน input วันที่ของร้าน (ลดความซับซ้อน ให้เซิร์ฟเวอร์แจ้งผลแทน)
- ถ้าแคมเปญไม่ได้ตั้งวันชำระสุดท้าย การขยายเวลาทำงานเหมือนเดิม

## 7. การตรวจสอบ
- SQL (`supabase/tests/preorder_*.test.sql`): ขยายได้ถึงสิ้นวันสุดท้าย · ขยายเกินวันสุดท้ายถูกปฏิเสธด้วย `past_last` · แคมเปญไม่มีวันสุดท้ายขยายได้เหมือนเดิม
- Deno (`supabase/tests/functions/preorder-admin`): การแปลง `past_last` เป็นข้อความไทย
- e2e (`e2e/preorderAdmin.supabase.e2e.mjs`): เคสร้อง error ที่แถวออเดอร์ · `e2e/preorderStore.supabase.e2e.mjs`: การ์ดแสดงวันชำระสุดท้าย
- `npm test` · `npm run test:fn` · `npm run build && npm run test:bundle`
