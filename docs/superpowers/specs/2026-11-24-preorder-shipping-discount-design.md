# ส่วนลดค่าส่งตามยอดซื้อ (สั่งล่วงหน้า) — Design

วันที่: 2026-11-24 · สถานะ: อนุมัติแล้ว

## 1. เจตนา (Intent)
ร้านต้องการจูงใจให้ลูกค้าซื้อมากขึ้นตอนสั่งล่วงหน้าแบบส่งพัสดุ โดยลดค่าส่งเป็นขั้นตามยอดซื้อ ลูกค้าเห็นแค่ยอด "ค่าส่ง" ที่ลดแล้ว

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ต้องไม่เกิด
- **เป้าหมาย:** ร้านตั้งขั้นส่วนลดค่าส่งได้หลายขั้นต่อแคมเปญ · ลูกค้าได้ส่วนลดขั้นสูงสุดที่ยอดถึง · ยอดคิดที่เซิร์ฟเวอร์
- **ไม่ใช่เป้าหมาย:** ใช้กับ POS หรือออเดอร์ปกติ · ส่วนลดสะสมหลายขั้น · ส่วนลดเป็นเปอร์เซ็นต์
- **ต้องไม่เกิด:** ค่าส่งติดลบ · ยอดก่อน VAT ที่ใช้นับขั้นไม่ตรงกับยอดในออเดอร์ · ส่วนลดที่ client ส่งมาถูกใช้

## 3. ข้อจำกัด (Constraints)
- ยอดทั้งหมดคิดที่ `src/lib/preorderPrice.js` และเซิร์ฟเวอร์ (`preorder` Edge Function) ใช้สำเนาเดียวกันผ่าน schedlib
- ไม่แก้ `src/lib/pricing.js` (ตัวคิดยอดกลาง) เพื่อไม่กระทบออเดอร์อื่น
- ส่วนลดสินค้าและคะแนนคิดตามลำดับเดิมของ `priceCampaignOrder`

## 4. แนวทาง (Approaches)
| ทาง | แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A (เลือก)** | เก็บขั้นในแคมเปญ (`deals` ชนิดใหม่) คำนวณใน `priceCampaignOrder` หลังคิดค่าส่งและคะแนนแล้ว | ขอบเขตแคบ เสี่ยงต่ำ | ถ้าจะใช้กับ POS ต้องทำอีกรอบ |
| B | เพิ่มเป็นกลไกกลางใน `pricing.js` | ใช้ได้ทุกออเดอร์ | กระทบยอดของทุกออเดอร์และสูตรที่ซ้ำกันหลายที่ |
| C | ใช้ระบบโปรเดิม (`withPromos`) | ไม่ต้องสร้างใหม่ | ไม่รองรับส่วนลดค่าส่งเป็นขั้น |

**เลือก A** ตามที่ผู้ใช้อนุมัติ

## 5. การออกแบบ (How)
**ข้อมูลในแคมเปญ** (`deals` เพิ่มชนิด `ship_off`):
```
{ kind: 'ship_off', tiers: [{ min: 300, value: 20 }, { min: 1000, value: 50 }] }
```
- `min` และ `value` เป็นบาท จำนวนเต็มหรือทศนิยม 2 ตำแหน่ง ไม่ติดลบ
- `min` ต้องเรียงขึ้นและไม่ซ้ำ · ไม่เกิน 10 ขั้น

**ฐานที่นับขั้น** = ยอดสินค้าหลังหักทุกประเภท (โปรสินค้า ปรับราคา คะแนน คูปอง) ก่อนค่าส่งและก่อน VAT
- ถ้าราคาเป็นแบบรวม VAT: ฐาน = ยอดหลังหัก ÷ (1 + อัตรา%) ตามสูตรของ `orderTotals`
- ดึงค่าจากผลของ `orderTotals` ของสินค้าอย่างเดียว ไม่คำนวณสูตรใหม่

**การคิดส่วนลด:**
1. หาขั้นสูงสุดที่ `ฐาน ≥ min` (ไม่มีขั้นที่ถึง = ไม่ได้ส่วนลด)
2. `shipDiscount = min(value ของขั้นนั้น, ค่าส่งรวมก่อนลด)`
3. ค่าส่งที่ลูกค้าเห็น = ค่าส่งรวม − `shipDiscount`
4. ใช้เฉพาะเมื่อ `fulfillment === 'delivery'`

**ลำดับในการคิด:** สินค้า → คะแนน → ฐานนับขั้น → ค่าส่งรวม → หักส่วนลดค่าส่ง → ยอดรวม
- คะแนนไม่ขึ้นกับส่วนลดค่าส่ง จึงไม่เกิดการวนคิดซ้ำ

**snapshot ในออเดอร์:** เพิ่ม `shipDiscount: { tier: min, amount }` และ `shippingFee` เป็นค่าหลังลด

## 6. การตัดสินใจที่ผมเลือกเอง (แก้ได้)
- ใช้ขั้นเดียวที่สูงสุด ไม่สะสม
- ลดได้ไม่เกินค่าส่งรวม
- ไม่มี VAT บนส่วนลดค่าส่งแยก (ค่าส่งเป็นยอดรวมแล้ว)
- ชื่อชนิด `ship_off` และชื่อฟิลด์ใน snapshot

## 7. สิ่งที่เหลือให้ผู้สร้างตัดสิน
- รูปแบบ UI ของตารางขั้นในหน้าแคมเปญ (แบบเดียวกับตารางโปรสินค้าเดิม)
- ข้อความที่แสดงลูกค้า (เช่น "ลดค่าส่ง 20 บาท เพราะยอดถึง 300 บาท")

## 8. การตรวจสอบ
- Unit: ไม่ถึงขั้น → ไม่ลด · ถึงขั้นพอดี → ลด · ถึงหลายขั้น → ขั้นสูงสุด · ค่าส่งน้อยกว่าส่วนลด → ลดเหลือ 0 · รับที่ร้าน → ไม่ลด · ราคารวม VAT → ฐานถูกถอด VAT
- Deno: เซิร์ฟเวอร์คิดตรงกับแอป · ส่วนลดที่ client ส่งมาไม่มีผล
- e2e: หน้าลูกค้าแสดงค่าส่งหลังลด
- `npm test`, `npm run test:fn`, `npm run build`, `npm run test:bundle`
