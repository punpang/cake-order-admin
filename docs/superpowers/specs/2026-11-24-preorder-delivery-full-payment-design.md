# สั่งล่วงหน้า: การจัดส่งต้องชำระเต็มจำนวนตอนสั่ง — Design

วันที่: 2026-11-24 · สถานะ: อนุมัติแล้ว

## 1. เจตนา (Intent)
ร้านไม่ต้องการรับออเดอร์จัดส่งที่จ่ายเพียงมัดจำ เพราะส่วนที่เหลือไม่มีคนจ่ายจะทำให้ค่าส่งและสินค้าเสียเปล่า ลูกค้าที่สั่งส่งพัสดุต้องชำระยอดเต็มตั้งแต่ตอนยืนยันออเดอร์

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ต้องไม่เกิด
- **เป้าหมาย:** ออเดอร์จัดส่งมีมัดจำเท่ายอดรวมเสมอ · ลูกค้าเห็นชัดว่าต้องชำระเต็ม
- **ไม่ใช่เป้าหมาย:** เปลี่ยนมัดจำของรับที่ร้าน · เปลี่ยนการคิดราคา ค่าส่ง หรือบัญชี
- **ต้องไม่เกิด:** ออเดอร์จัดส่งที่มีมัดจำน้อยกว่ายอดรวม · รับที่ร้านถูกบังคับให้จ่ายเต็ม

## 3. ข้อจำกัด (Constraints)
- เซิร์ฟเวอร์เป็นผู้คิดมัดจำ ห้ามรับค่ามัดจำจาก client
- การส่งพัสดุยังต้องชำระครบก่อน (ฐานข้อมูล `punpang_preorder_set_shipping` เดิม)

## 4. แนวทาง (Approaches)
| ทาง | แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A (เลือก)** | ตอนสร้างออเดอร์จัดส่ง ตั้งมัดจำ = ยอดรวม | ตรงกับกติกา ไม่แก้ฐานข้อมูล | ลูกค้าที่จ่ายยากสั่งน้อยลง |
| B | มัดจำได้ แต่ต้องชำระเต็มก่อนจัดส่ง | ไม่เปลี่ยนการไหลเงิน | ไม่ตรงกับกติกาที่ผู้ใช้ต้องการ |

**เลือก A** ตามที่ผู้ใช้ยืนยัน

## 5. การออกแบบ (How)
- Edge Function `preorder` (action `create`): ถ้า `fulfillment === 'delivery'` ตั้ง `deposit = total` (ปัดเป็นสตางค์เหมือนเดิม) ส่วนรับที่ร้านใช้ `deposit_percent` เดิม
- หน้าลูกค้า (`src/views/store/StorePreorder.vue`): เมื่อเลือกส่งพัสดุ แสดงข้อความว่า "การจัดส่งต้องชำระเต็มจำนวนตอนสั่ง" และยอดมัดจำที่แสดงเป็นยอดเต็ม
- ไม่เปลี่ยนฐานข้อมูล ไม่เปลี่ยนบัญชี

## 6. การตัดสินใจที่ผมเลือกเอง (แก้ได้)
- ข้อความในหน้าลูกค้า: ใช้ "ชำระเต็มจำนวน" ตามคำของผู้ใช้
- กติกานี้ใช้กับทุกแคมเปญโดยไม่มีตัวเลือกให้ตั้งเป็นรายแคมเปญ

## 7. การตรวจสอบ
- Deno: ออเดอร์จัดส่งได้มัดจำเท่ายอดรวม · รับที่ร้านได้มัดจำตามเปอร์เซ็นต์เดิม
- e2e: หน้าลูกค้าแสดงข้อความชำระเต็มเมื่อเลือกส่งพัสดุ
- `npm test`, `npm run test:fn`, build, bundle
