# ออกแบบ: บันเดิ้ลแบบเลือกตัวเลือกหนึ่งตัวแล้วดูทุกชุดที่ผูกอยู่ (แทนตารางคู่ใน PR #227)

> เอกสารแผน ยังไม่มีการแก้โค้ด รอผู้ใช้อนุมัติก่อนเริ่มทำ

## ที่มาและการตัดสินใจ (ผู้ใช้อนุมัติแล้ว 2026-11-27)
1. **แทน** ตารางคู่ต่อกลุ่มใน PR #227 ด้วยหน้าแบบเลือกตัวเลือกหนึ่งตัว ไม่ทำเป็นหน้าซ้อนสองหน้า (ลดขนาด JS และความสับสน) PR #227 จะถูกปิดหรือเขียนใหม่หลังแผนนี้ได้รับอนุมัติ
2. **ราคาปกติ** แสดงตามที่ตัวเลือกคิดราคาจริง (ตัวเลือกแบบคงที่หรือแบบตามขนาด) ผ่าน `optionPrice`/`regularTotal` · **ส่วนลดของชุด** ยังตั้งตามขนาดเสมอ (`discount[sizeId]`) และแยกประเภท/รูปแบบได้ตามเดิม
3. **กติกาการใช้ชุดซ้อน** ตามโค้ดจริง `bundleWinners` (`src/lib/pricing.js`): เรียงตามจำนวนตัวเลือกมากไปน้อย แล้วตามส่วนลดมากไปน้อย ชุดจะถูกใช้เมื่อไม่มีตัวเลือกใดของชุดถูกใช้ไปแล้ว ชุดที่มีตัวเลือกมากกว่าจึงได้ก่อนเสมอ และถ้ามีชุดหลายตัวเลือกใช้ได้ ชุดตัวเลือกเดียวจะไม่นับ

## เป้าหมาย
- เลือกตัวเลือกรอง 1 ตัว (เช่น คิทแคท) แล้วเห็นทุกชุดที่มีตัวเลือกนั้น ทั้งชุด 2 ตัวและ 3 ตัวขึ้นไป
- เปิดตัวเลือกอื่น (เช่น เชอร์รี่) แล้วเห็นว่าผูกกับชุดไหนแล้วบ้าง
- สร้างชุดข้ามกลุ่มตัวเลือกรองได้ (ตามคอมเมนต์ใน `pricing.js` ชุดข้ามกลุ่มใช้ได้เฉพาะตัวเลือกรอง ต้องยืนยันขอบเขตนี้ในขั้นที่ 1)
- ไม่เปลี่ยนสูตรราคา `pricing.js` และรูปแบบข้อมูล `db.bundles`

## ไม่ทำ
- ไม่ทำตารางคู่ต่อกลุ่มแบบ PR #227 อีก
- ไม่เปลี่ยนหน้าแก้ไขชุดเดิม (`ManageBundleEdit.vue`) ยกเว้นลิงก์เข้าหน้า

## ขั้นตอน (ทีละขั้น ทดสอบแล้วค่อยไปต่อ)
1. ยืนยันขอบเขต "ข้ามกลุ่มเฉพาะตัวเลือกรอง" จากโค้ดจริงและ `MAIN` ใน `pricing.js` ก่อนเขียนโค้ดใด ๆ
2. ฟังก์ชันล้วนใน `src/lib/bundleByOption.js`: หาชุดทั้งหมดที่มีตัวเลือกนั้น · จัดกลุ่มตามจำนวนตัวเลือก · สถานะการใช้จริงตาม `bundleWinners` (ใช้ / ถูกข้ามเพราะตัวเลือกซ้ำ) · ราคาปกติรวมและส่วนลดต่อขนาด · ไฟล์เทสต์คู่กัน
3. หน้า `ManageBundleByOption.vue` ที่เส้นทางใหม่ เลือกตัวเลือก → รายการชุด → แตะเพื่อแก้ผ่านหน้าชุดเดิม
4. ปุ่มสร้างชุดใหม่จากตัวเลือกที่เลือก เลือกตัวเลือกคู่ข้ามกลุ่มรองได้ ใช้ `checkBundle` เดิมตรวจก่อนบันทึก
5. แก้คอมเมนต์ที่ `pricing.js` บรรทัด 198 ให้ตรงกับโค้ดจริง (เอกสาร/คอมเมนต์เท่านั้น ไม่แก้พฤติกรรม)
6. วัดขนาด JS เทียบงบ 935 KB ก่อนรวม ถ้าเกินต้องขอผู้ใช้อนุมัติงบก่อน

## การทดสอบ
- เทสต์ฟังก์ชันสำหรับการนับ สถานะการใช้ และราคา รวมกรณีในตัวอย่าง: เชอร์รี่+คิทแคท+โอริโอ้ ใช้ชุด 3 ตัวเลือก ชุด 1 และ 2 ถูกข้าม
- e2e ของหน้าใหม่ ใช้ข้อมูลจำลองในหน่วยความจำเท่านั้น และ smoke test ของทุก route
- `npm test` และ `npm run build` ต้องผ่าน

## ขนาดและงบ
- ขนาด JS บน `main` = 932.6 KB, งบรวม 935 KB
- ตารางคู่ใน PR #227 เพิ่มมา 4.3 KB ทำให้เกินงบ 1.9 KB
- หน้าใหม่นี้คาดว่าจะใหญ่กว่า จึงต้องวัดหลังขั้นที่ 3 และขออนุมัติงบก่อนรวม

## คำถามที่ยังเปิด
- ยืนยันขอบเขตข้ามกลุ่มตามข้อ 1 ของขั้นตอน
- ตอนสร้างชุดใหม่ ควรจำกัดจำนวนตัวเลือกสูงสุดต่อชุดหรือไม่ (ปัจจุบันระบบไม่จำกัด)
