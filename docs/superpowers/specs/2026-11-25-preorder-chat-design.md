# สั่งล่วงหน้าในแชท: ดูออร์เดอร์สั่งล่วงหน้าของลูกค้าได้จากหน้าแชท — Design (ขนาดเล็ก)

วันที่: 2026-11-25 · สถานะ: รอการอนุมัติ

## 1. เจตนา
พนักงานกำลังคุยกับลูกค้าในแชท แต่ไม่เห็นว่าลูกค้าคนนั้นมีออร์เดอร์สั่งล่วงหน้าค้างอยู่ ต้องออกจากแชทไปหาเอง ต้องการให้เห็นและเปิดออร์เดอร์นั้นได้จากแผงรายละเอียดลูกค้าในแชท

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ต้องไม่เกิด
- **เป้าหมาย:** ในแผง "ข้อมูลลูกค้า" ของแชท มีส่วน "สั่งล่วงหน้า" แสดงออร์เดอร์สั่งล่วงหน้าที่ยังไม่ปิดของลูกค้าคนนั้น และกดเปิดหน้าสั่งล่วงหน้าได้
- **ไม่ใช่เป้าหมาย:** ทำรายการ (รับเงิน บันทึกการส่ง) จากแชท (เป็นข้อ 4 ที่ยังไม่ทำ) · แสดงในรายการแชทภาพรวม
- **ต้องไม่เกิด:** เห็นออร์เดอร์ของลูกค้าคนอื่น · พนักงานที่ไม่มีสิทธิ์เห็นข้อมูล · หน้าแชทโหลดช้าเพราะโหลดข้อมูลสั่งล่วงหน้าทุกครั้ง

## 3. ข้อจำกัด
- ออร์เดอร์สั่งล่วงหน้าอยู่ในตารางแยก ไม่อยู่ใน `db.orders` ของแชท จึงต้องดึงจากเซิร์ฟเวอร์
- ระบบดึงรายการ `list` ของ `preorder-admin` มีเพดาน 200 รายการล่าสุด และไม่มีรหัสลูกค้า จึงใช้กรองตามลูกค้าไม่ได้ ต้องเพิ่ม action ใหม่
- เห็นได้เฉพาะผู้มีสิทธิ์ `managePreorder` หรือ `manage`
- ข้อมูลที่ส่งกลับมีเฉพาะที่ใช้แสดง: รหัส สถานะ วันรับ และยอดค้าง

## 4. แนวทาง
| ทาง | แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A (เลือก)** | action ใหม่ `customerOrders` ใน `preorder-admin` รับ `customerId` คืนออร์เดอร์ที่ยังไม่ปิด โหลดเมื่อเปิดแผงลูกค้า | ตรงลูกค้า ไม่มีเพดาน 200 โหลดเฉพาะตอนเปิดแผง | ต้อง Release `preorder-admin` |
| B | เพิ่ม `customerId` ใน action `list` แล้วกรองที่หน้าเว็บ | ไม่มี action ใหม่ | ยังติดเพดาน 200 และดึงข้อมูลทุกออร์เดอร์ |

**เลือก A** เพราะแยกหน้าที่ชัดและไม่ติดเพดาน

## 5. การออกแบบ
- `supabase/functions/preorder-admin/index.ts`: action `customerOrders` รับ `customerId` (ต้องเป็น uuid ของลูกค้า) คืนออร์เดอร์ที่สถานะไม่ใช่ `cancelled`/`expired` และไม่ใช่ `delivered` พร้อม id รหัส สถานะ วันรับ ยอดค้าง และ `payDueAt`
- `src/lib/preorderCustomerOrders.js` (ฟังก์ชันล้วน): กรองและเรียงรายการที่จะแสดง พร้อมเทสต์ Node
- `src/views/Chat.vue`: ในแผง "ข้อมูลลูกค้า" เพิ่มส่วน "สั่งล่วงหน้า" เมื่อมีลูกค้าที่ผูกแล้วและผู้ใช้มีสิทธิ์ · โหลดเมื่อเปิดแผง · แสดงสถานะว่าง/กำลังโหลด/ผิดพลาด · กดรายการไปหน้า `/admin/preorders`
- เทสต์ Deno: สิทธิ์ 403 · ไม่มี `customerId` 400 · ไม่คืนออร์เดอร์ของลูกค้าอื่น

## 6. การตัดสินใจที่ผมเลือกเอง (แก้ได้)
- ส่วนนี้อยู่หลังส่วน "ออร์เดอร์ที่ยังไม่ปิด" เดิม
- ไม่โหลดซ้ำเมื่อเปลี่ยนแชทภายในลูกค้าคนเดิม
- ถ้าลูกค้ายังไม่ได้ผูก แสดงข้อความให้ผูกก่อน

## 7. การตรวจสอบ
- Node: ฟังก์ชันกรองและเรียง
- Deno: action `customerOrders` ตามเคสข้างบน
- e2e: แผงลูกค้าในแชทแสดงออร์เดอร์สั่งล่วงหน้าเฉพาะของลูกค้าคนนั้น
- `npm test` · `npm run test:fn` · build · bundle (ถ้าเกินเพดาน หยุดและขออนุมัติพร้อมตัวเลข)
