# ระบบสั่งล่วงหน้า: จำกัดการส่งข้อความต่อรอบ (SMS throttle)

**วันที่:** 2026-11-25 · **สถานะ:** อนุมัติแล้ว

## เหตุผล
ปริมาณปัจจุบันไม่เกิน 200 ข้อความต่อวัน แต่ยังไม่มีเพดาน หากส่งพร้อมกันมากเกินไปในรอบเดียว เกตเวย์ SMS อาจรับไม่ทันและงานล้ม

## เป้าหมาย
- ส่งสูงสุด 50 ข้อความต่อรอบของ `preorder-notify` (รันทุก 5 นาที)
- ข้อความที่ล้มเหลวถูกลองใหม่ในรอบถัดไปโดยไม่ส่งซ้ำ
- แจ้งยอดคงเหลือก่อนวันรับส่งได้ช่วง 09:00–19:59 น. (เดิม 09:00–09:04)

## ไม่ทำ
- ไม่สร้างตารางคิวใหม่ และไม่มี migration
- ไม่เปลี่ยนข้อความหรือช่องทาง (LINE ก่อน แล้ว SMS สำรอง)

## แนวทาง (เลือกแล้ว)
ตัวเลือกที่พิจารณา: (1) ตารางคิวและงาน worker แยก, (2) จำกัดจำนวนต่อรอบในงานเดิม, (3) เปิดให้ส่งได้ทุกรอบโดยไม่มีเพดาน
เลือก (2) เพราะปริมาณต่ำ ไม่ต้องเพิ่มโครงสร้าง และใช้กลไกการจองสิทธิ์เดิมกันส่งซ้ำ

## รายละเอียด
- `SEND_CAP_PER_RUN = 50` ใน `_shared/preorderNotifyPlan.ts`
- `runWithCap` นับเฉพาะรายการที่ส่งจริงหรือล้มเหลว (`skipped` ไม่กินโควตา)
- ลำดับ: เตือนก่อนหมดเวลา → หมดเวลา → แจ้งยอดคงเหลือก่อนวันรับ
- `notifyOrderEvent` คืนผลการส่งแทน `void`

## การตรวจสอบ
- Deno: เพดาน 50, รายการที่ข้ามไม่กินโควตา, หน้าต่างเวลาขอบ 09:00 / 19:59 / 20:00
- ค่า 50 เป็นการตัดสินใจของผู้พัฒนา ต้องยืนยันขีดจำกัดของเกตเวย์ก่อนใช้จริง
