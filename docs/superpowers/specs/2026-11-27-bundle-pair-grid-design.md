# ออกแบบ: ตารางตั้งราคาชุด (คู่ตัวเลือก) ต่อกลุ่ม

> เอกสารคัดจากแผนที่อนุมัติ (ปรับล่าสุด 2026-11-27) ยังไม่มีการแก้โค้ด


## Context
เจ้าของร้านตั้งราคาชุด (ส่วนลดเมื่อเลือก 2 ตัวเลือกคู่กัน) ทีละคู่ในหน้าแก้ไขชุด 4 ขั้น แล้วสับสนว่าคู่ไหนตั้งแล้ว คู่ไหนยังไม่ตั้ง และคู่ที่คล้ายกันต้องกรอกซ้ำ
ตัวอย่างจริงในกลุ่ม "ขอบบนเค้ก" (ทุกตัวเลือก +50): เชอร์รี่+คิทแคท ลด 100, คิทแคท+เบงเบง ลด 10, โอริโอ้+คิทแคท ยังไม่มีชุด
ผู้ใช้ยืนยัน: **แต่ละคู่ราคาต่างกันได้** (ไม่ใช่กฎเดียวทั้งกลุ่ม) และเลือกแนวทาง **ตารางคู่ต่อกลุ่ม**

## ขั้นที่ 0: เก็บแผนลง repo (ทำก่อนทุกอย่าง)
1. สร้างสาขา `claude/bundle-pair-grid-plan` จาก `origin/main`
2. เขียนไฟล์ `docs/superpowers/specs/2026-11-27-bundle-pair-grid-design.md` คัดจากหัวข้อทั้งหมดของแผนนี้ (ไม่แก้โค้ดใด ๆ)
3. commit แล้ว push ขึ้นสาขานั้น (`git push -u origin`) ไม่เปิด PR จนกว่าผู้ใช้สั่ง
4. ทำขั้นนี้ก่อนเริ่มโค้ด เพื่อให้แผนอยู่ถาวรแม้ย้ายแชท

## เป้าหมาย / ไม่ทำ
- เป้าหมาย: เห็นทุกคู่ในกลุ่มบนจอเดียว ช่องว่าง = ยังไม่ตั้ง · กรอกราคาในช่องได้เลย · มีราคาแนะนำจากคู่ที่คล้ายกัน แตะครั้งเดียวรับ · เลือกหลายช่องแล้วใส่ราคาเดียวกันทีเดียว
- ไม่ทำ: ไม่เปลี่ยนสูตรคำนวณราคา (`pricing.js`) และรูปแบบข้อมูลชุด (`db.bundles`) · ไม่ทำชุด 3 ตัวเลือกขึ้นไปหรือข้ามกลุ่มในตาราง (ยังใช้หน้าเดิม)
- ห้ามพัง: ชุดเดิมทุกชุดต้องคำนวณเหมือนเดิม ราคาที่ลูกค้าเห็นต้องไม่เปลี่ยนถ้าไม่ได้แก้ในตาราง

## แนวทาง (ผู้ใช้เลือก ก)
- **ก. ตารางคู่ต่อกลุ่ม (เลือก)** เห็นครบ แก้ทั้ง "มองไม่เห็นว่าขาดคู่ไหน" และ "กรอกซ้ำ"
- ข. รายการคู่ที่ยังไม่ตั้งในหน้าเดิม: งานเล็กกว่า แต่ไม่เห็นภาพรวม
- ค. ปุ่มคัดลอกราคาในหน้าแก้ไขชุด: งานน้อยสุด แต่ยังสร้างทีละคู่

## การออกแบบ (ข้อที่ผมตัดสินเอง ให้ผู้ใช้ตรวจ)
1. **หน้าใหม่** `ManageBundleGrid.vue` เส้นทาง `/admin/settings/bundles/grid` เข้าจากปุ่ม "ตารางราคาคู่" ในหน้ารายการชุด (`ManageBundles.vue`)
2. **เลือกกลุ่ม + ขนาด** ด้านบน (แท็บขนาดเหมือนหน้าแก้ไขชุดเดิม) ตารางแสดงครึ่งบนของเมทริกซ์ (คู่ไม่ซ้ำ)
3. **ช่องในตาราง** ตามสถานะ
   - มีชุดคู่นี้: แสดงส่วนลดของขนาดที่เลือก (ค่า "ทุกชนิดเค้ก")
   - มีราคาแยกชนิด/สไตล์ หรือปิดใช้งาน: แสดงเครื่องหมายเล็ก แตะแล้วเปิดหน้าแก้ไขชุดเดิม ไม่แก้ในตาราง
   - ยังไม่มีชุด: ช่องว่าง ถ้ามีราคาแนะนำ แสดงตัวเลขจาง
4. **ราคาแนะนำ** = ส่วนลดที่ใช้บ่อยที่สุดของคู่อื่นในกลุ่มเดียวกันที่ "ราคาตัวเลือกรวมเท่ากัน" ในขนาดนั้น (ไม่มีคู่แบบนั้น = ไม่แนะนำ) ฟังก์ชันล้วนใหม่ใน `src/lib/bundleGrid.js`
5. **การแก้ไข** แตะช่อง → กรอกตัวเลข (หรือรับราคาแนะนำ) · โหมดเลือกหลายช่อง → ใส่ราคาเดียว · ตัวเลือก "ใช้กับทุกขนาด"
   - ช่องว่าง → สร้างชุดใหม่ 2 ตัวเลือก ชื่ออัตโนมัติ "A + B" ใช้ได้กับทุกชนิดเค้ก ส่วนลดเฉพาะขนาดที่กรอก
   - ช่องมีค่า → แก้ `discount[sizeId]` ของชุดนั้น
   - ใส่ 0 หรือลบค่า → ไม่ลบชุด แต่ถามยืนยันก่อนปิดใช้งาน
6. **ตรวจก่อนบันทึก** ใช้ `checkBundle` / `findDuplicate` (`src/lib/bundleEditor.js`) และเพดานส่วนลด `bundleAmountCapped` (`src/lib/pricing.js`) แจ้งเตือนเป็นภาษาไทยในช่องที่ผิด
7. **บันทึก** ผ่านกลไกเดิมของ `db.bundles` (configSync) ทีละชุดที่เปลี่ยน ปุ่ม "บันทึก" เดียวด้านล่าง ไม่บันทึกอัตโนมัติ

## ส่วนเพิ่ม: ราคาแยกตามชนิดเค้กและสไตล์ (ตัดสินใจแล้ว)
- กติกาเดิมในระบบ (`pricing.js` บรรทัด 188–190) ใช้อยู่แล้ว ไม่ต้องถามใหม่: ราคาต่อขนาด = ราคาตามชนิด (`typeDiscount`) ถ้ามี > ไม่มีก็ใช้ราคา "ทุกชนิด" (`discount`) ดังนั้นคู่ที่ไม่ตั้งราคาเฉพาะชนิดจะใช้ราคาทุกชนิดอัตโนมัติ
- สไตล์: ถ้า `styleMode[styleId] === 'own'` ใช้ `styleDiscount[styleId][sizeId]` (ช่องว่าง = 0) ไม่งั้นใช้กติกาชนิดข้างบน
- **ตัวเลือกมิติด้านบนของหน้าตาราง:** เลือกได้ 3 แบบ — "ทุกชนิด (ค่าตั้งต้น)" / ชนิดเค้กแต่ละชนิด / สไตล์แต่ละแบบ (แสดงเฉพาะที่ร้านเปิดใช้)
- **ช่องในตาราง** แสดงค่าที่มีผลจริงในมิตินั้น:
  - ตั้งเฉพาะมิตินั้น: ตัวเลขปกติ
  - รับค่าจากทุกชนิด: ตัวเลขสีเทา แตะแล้วตั้งราคาเฉพาะ (เขียนลง `typeDiscount` ของชนิดนั้น)
  - ไม่มีชุด: ช่องว่าง + ราคาแนะนำ
- **การเขียนข้อมูล:** มิติ "ทุกชนิด" เขียนลง `discount[sizeId]` · ชนิดเขียนลง `typeDiscount[typeId][sizeId]` · สไตล์เขียนลง `styleDiscount[styleId][sizeId]` และตั้ง `styleMode[styleId] = 'own'`
- ฟังก์ชันล้วนใหม่ใน `src/lib/bundleGrid.js` ใช้ `bundleAmount` เดิมเป็นตัวตัดสินค่าที่มีผล เพื่อไม่ให้ตารางคำนวณต่างจากหน้าลูกค้า
- เทสต์เพิ่ม: ค่าที่มีผลของคู่ที่ไม่ตั้งเฉพาะชนิด = ค่าทุกชนิด · สไตล์ own ช่องว่าง = 0 · การเขียนลงมิติที่ถูกต้องและไม่แตะมิติอื่น
