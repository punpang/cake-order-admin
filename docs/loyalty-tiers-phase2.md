# ระดับสมาชิก · เฟส 2: สิทธิประโยชน์ตามระดับ (แผน)

**สถานะ (2026-11-22):** วางแผนแล้ว · **ยังไม่ทำ** · รอคำสั่ง "ทำ" · เริ่มหลังเปิดโหมดทดลองและมีข้อมูล 1–2 สัปดาห์ (ผู้ใช้สั่ง) · เฟส 1 ดูที่ `docs/loyalty-tiers.md`

## เป้าหมาย
- เจ้าของร้านตั้งสิทธิประโยชน์ของแต่ละระดับเองได้ (ชนิด ความถี่ จำนวน) โดยไม่ต้องแก้โค้ด
- ชุดตัวอย่างจาก PDF 4 ชุดเป็นจุดเริ่มต้นให้เลือก ไม่ใช่ค่าตายตัว
- สิทธิ์ออกเฉพาะโหมด **ใช้จริง** และไม่ออกย้อนหลัง

## ต้องให้ผู้ใช้ตัดสินก่อนทำ
1. **สิทธิ์ต่อระดับ:** ชนิด (แต้มต้อนรับ · คูปองส่วนลด · คูปองส่วนลดค่าส่ง · ส่วนลด % เฉพาะเค้ก · ตัวคูณแต้มเดือนเกิด · สิทธิ์พิเศษที่พนักงานเห็น) · ความถี่ (สมัคร · รายเดือน · รายไตรมาส · เดือนเกิด) · จำนวน → ผู้ใช้กรอกตาราง ผมไม่กำหนดตัวเลขเอง
2. **วิธีออกคูปอง:** (แนะนำ) งาน pg_cron รายวันออกคูปองที่ยังไม่มี · ทางเลือก: ออกตอนลูกค้าเปิดบัญชีหรือสั่งซื้อ (ลูกค้าที่ไม่เข้าแอปจะไม่ได้รับ)
3. **เงื่อนไขการได้สิทธิ์:** ต้อง Active ณ วันออกหรือไม่ (แนะนำ: ใช่) · คูปองที่ออกแล้วใช้ได้ตามวันหมดอายุ
4. **เดือนเกิด:** ใครกรอก (แนะนำ: ลูกค้ากรอกครั้งเดียว แก้ได้เฉพาะแอดมินพร้อมเหตุผล) · เงื่อนไขก่อนได้สิทธิ์เดือนเกิด (แนะนำ: อยู่ระดับนั้น ≥30 วันก่อนเดือนเกิด และ Active)
5. **ซ้อนสิทธิ์:** ตัวคูณเดือนเกิดซ้อนกับตัวคูณระดับหรือไม่ (แนะนำ: ไม่ซ้อน ใช้ค่าสูงสุด) · "เค้ก" ในส่วนลดเฉพาะเค้ก (แนะนำ: รายการหลักสำเร็จและสั่งทำ ไม่รวมตัวเลือกเสริม)

## ข้อเท็จจริงที่ตรวจแล้ว
- โหมดคูปองที่มี: fixed · spend · product · credit (`src/lib/coupons.js`) ต้องเพิ่ม `shipping` และ `cakePct`
- `punpang_records` PK = (collection, id) ใช้รหัสตายตัวกันออกซ้ำได้ · collection `coupons` มีอยู่แล้ว
- pg_cron ใช้งานอยู่แล้ว (เช่น `punpang-retention`)
- ความยินยอมโปรโมชัน `promoOptIn` และ `src/lib/promoConsent.js` มีอยู่แล้ว
- งบบันเดิล 882.4 / 886 KB เหลือ ~3.6 KB → เฟสนี้ต้องขอเพิ่มงบ (หยุดถามก่อนเพิ่ม)

## สิ่งที่จะทำเมื่อสั่ง "ทำ"
**ฐานข้อมูล (migration ใหม่ · ต้องอนุมัติ Release แยก)**
- config `tierBenefits` ใน `punpang_kv`: รายการ `{id, level, kind, freq, amount, on}` ตรวจค่าแบบเดียวกับ `memberLevels` (ค่าผิด = ไม่ออกสิทธิ์)
- โหมดคูปอง `shipping` (ลดค่าส่ง สูงสุด X บาท ใช้กับออร์เดอร์จัดส่งเท่านั้น) และ `cakePct` (ลด % เฉพาะรายการเค้ก) ใน `punpang__coupon_entry_ok` และ `src/lib/coupons.js`
- `punpang_tier_benefits_issue(p_period)`: ออกคูปองรหัส `tb:<id>:<customerId>:<period>` ด้วย `on conflict (collection, id) do nothing` · เฉพาะโหมดใช้จริง · ข้ามลูกค้าที่ถูกลบ · ไม่ย้อนหลัง
- งาน pg_cron `punpang-tier-benefits` รายวัน เรียกฟังก์ชันข้างบน
- เดือนเกิด `customer.data.birth = {m, at, by}` ล็อกหลังกรอก · บันทึกผ่าน RPC ที่ตรวจสิทธิ์ ไม่เขียนตรงจากไคลเอนต์
- แต้มต้อนรับ/แต้มรายเดือน ใช้กลไกปรับแต้มเดิม (migration `20261110170531`) ไม่สร้างกลไกใหม่

**Edge Function `customer-auth`:** แนบรายการคูปองที่ใช้ได้ให้ลูกค้า ไม่มียอดสะสม

**แอป**
- จัดการ → คะแนน & รางวัล → แท็บระดับ: ตารางตั้งสิทธิ์ + ปุ่มโหลดชุดตัวอย่าง
- บัญชีลูกค้า: ป้ายสิทธิ์ (กฎ 3 บรรทัด) · ฟอร์มเดือนเกิดครั้งเดียว
- หน้าขาย: แสดงเฉพาะคูปองที่ใช้ได้ของลูกค้า

**PDPA**
- `docs/pdpa.md` ข้อ 2: แถว "เดือนเกิดสมาชิก" ฐานความยินยอม (รอยืนยัน) · ข้อ 3: ระยะเก็บ
- ถ้อยคำฉบับลูกค้าต้องให้ผู้ใช้ยืนยันก่อนเผยแพร่

**การแจ้งลูกค้า:** เฉพาะผู้ที่ `promoOptIn` ผ่าน `src/lib/promoConsent.js`
