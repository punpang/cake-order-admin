# PDPA: บันทึกการประมวลผลข้อมูลส่วนบุคคล (ฉบับใช้จริง)

เอกสารภายในสำหรับเจ้าของร้านและทีมดูแลระบบ อัปเดตตามระบบที่ deploy จริง ณ 2026-11
ข้อความที่ลูกค้าเห็นอยู่ที่ `src/lib/legalDefaults.js` (ประกาศความเป็นส่วนตัว เงื่อนไข คุกกี้) และแก้ได้ที่ `/admin/settings/legal`
ข้อความนี้ **ยังไม่ใช่คำแนะนำทางกฎหมาย** ควรให้ที่ปรึกษากฎหมายตรวจก่อนใช้จริง

## 1. ผู้ควบคุมข้อมูลและผู้ประมวลผล
- ผู้ควบคุมข้อมูล: เจ้าของร้าน (บุคคลธรรมดา) ข้อมูลติดต่อตั้งที่ จัดการ → ร้าน → ใช้ที่อยู่ตามข้อมูลกฎหมาย และ `/admin/settings/legal`
- ไม่มีการแต่งตั้ง DPO เนื่องจากขนาดการประมวลผลและประเภทข้อมูลไม่เข้าเงื่อนไขบังคับ (ให้ที่ปรึกษายืนยัน)

| ผู้ให้บริการ | หน้าที่ | ข้อมูลที่ไปถึง | ที่ตั้ง |
|---|---|---|---|
| Supabase (`itleduijrckxdbhhuooi`) | ฐานข้อมูล Edge Functions | ทุกประเภทในข้อ 2 | สิงคโปร์ |
| Cloudflare (Pages, Worker `punpang-files`, R2 `punpang-public` / `punpang-private`) | เว็บไซต์ `cake-order-admin.pages.dev` และที่เก็บไฟล์รูป/สลิป/ไฟล์แชท | รูปงาน สลิป ไฟล์แชท | ตามผู้ให้บริการ |
| Meta (Facebook Page) | รับ/ส่งข้อความ | ชื่อโปรไฟล์ PSID ข้อความ ไฟล์แนบ | สหรัฐอเมริกา (ตามผู้ให้บริการ) |
| SMS Gateway ของร้าน (เครื่องโทรศัพท์) + ผู้ให้บริการมือถือ | ส่ง OTP และแจ้งเตือน | เบอร์โทร เนื้อความ OTP | ประเทศไทย |
| Telegram | แจ้งเตือนทีมภายในร้าน | ชื่อลูกค้า เลขออร์เดอร์ ข้อความสั้น (ไม่มี OTP/PIN) | ตามผู้ให้บริการ |
| ผู้ให้บริการขนส่ง (ถ้าใช้) | จัดส่ง | ชื่อ เบอร์ ที่อยู่ | ไทย |
| Anthropic (Claude API) — **เฉพาะเมื่อร้านเปิดใช้บอท AI** (`bot.ai.enabled`) | ตอบแชทคำถามทั่วไปที่กฎตอบไม่ได้ | ข้อความล่าสุดของลูกค้าที่ผ่าน PII gate (ไม่มีเบอร์ อีเมล เลขออร์เดอร์ เลขยาว หรือชื่อโปรไฟล์) และข้อมูลร้าน/FAQ/รายการสินค้าที่เปิดขาย ไม่มีประวัติแชท ออร์เดอร์ หรือข้อมูลบัญชี | สหรัฐอเมริกา |
| Google (Firebase Cloud Messaging) — เฉพาะเครื่องที่ติดตั้งแอป Android และยอมรับการแจ้งเตือน | ส่งแจ้งเตือนเข้าเครื่อง | พนักงาน: หัวข้อและข้อความแจ้งเตือน (อาจมีเลขออร์เดอร์ ยอด ชื่อลูกค้า) · ลูกค้า: ข้อความคงที่ "ร้านตอบกลับข้อความของคุณ" (ไม่มีเนื้อหาแชท) · โทเค็นของเครื่อง | ตามผู้ให้บริการ |
| Anthropic (Claude API) และ/หรือ Cloudflare (Workers AI) — **เฉพาะเมื่อร้านเปิดอ่านสลิปด้วย OCR** (ตั้งค่า `slipQr.ocr`) | อ่านยอด วัน-เวลา เลขบัญชีผู้รับ รหัสอ้างอิงจากรูปสลิป (ทั้งแชทและหน้าสั่งของลูกค้า) | รูปสลิปทั้งใบตามที่ธนาคารแสดง (เช่น ชื่อ เลขบัญชีบางส่วน ยอด เวลา รหัสอ้างอิง) · มีเพดานจำนวนครั้งต่อชั่วโมง/ต่อแชท | สหรัฐอเมริกา / ตามผู้ให้บริการ |

**ไม่ใช้:** การวิเคราะห์เว็บ/โฆษณาติดตามข้ามเว็บ · LINE OA (ยังไม่เปิดใช้งานจริง ถ้าเปิด ต้องอัปเดตประกาศและบันทึกนี้ก่อน)
ประกาศฉบับใหม่ระบุว่าร้าน "อาจเปิดใช้" AI ได้ จึงต้องแจ้งลูกค้าไว้ก่อนแม้ยังไม่เปิด การเปิดใช้จริงไม่ต้องแก้ประกาศ แต่ควรบันทึกวันที่เปิดในบันทึกนี้

## 2. รายการข้อมูลและวัตถุประสงค์

| หมวด | ข้อมูล | แหล่งที่มา | วัตถุประสงค์ | ฐาน |
|---|---|---|---|---|
| ติดต่อ | ชื่อ เบอร์ LINE ID | ลูกค้า / พนักงาน | ออร์เดอร์ ติดต่อ | สัญญา |
| แชท | PSID ชื่อโปรไฟล์ ข้อความ ไฟล์แนบ | Facebook Webhook | ตอบแชท ติดตามออร์เดอร์ | สัญญา / ประโยชน์โดยชอบ |
| บัญชี | เบอร์ PIN (แฮช PBKDF2-SHA256 210,000 รอบ) OTP (แฮชพร้อม salt) เซสชัน (แฮช) | ลูกค้า | ยืนยันตัวตน | สัญญา / ประโยชน์โดยชอบ |
| ออร์เดอร์ | รายการ ตัวเลือก วันนัด ที่อยู่/พิกัด (จำ 10 ที่) ข้อความเค้ก วันเกิดผู้รับ หมายเหตุ | ลูกค้า / พนักงาน | ผลิตและส่งมอบ | สัญญา |
| การเงิน | ยอด ช่องทาง สลิป | พนักงาน / ลูกค้า | รับชำระ ภาษี บัญชี | สัญญา / กฎหมาย |
| สิทธิประโยชน์ | คะแนน คูปอง ประวัติกาชา รีวิว | ระบบ | โปรแกรมสมาชิก | สัญญา |
| ยินยอม | เวอร์ชันเอกสาร วันเวลา วิธีที่ยินยอม (`consents`) | ระบบ | หลักฐานการยินยอม | กฎหมาย |
| สุขภาพ | การแพ้อาหาร | ลูกค้า (ยินยอมชัดแจ้ง) | ผลิตอย่างปลอดภัย | ความยินยอม |
| รูปงาน | รูปสินค้าที่ทำเสร็จ | พนักงาน | แสดงผลงาน | ประโยชน์โดยชอบ (คัดค้านได้) |
| เทคนิค | IP (จำกัดการขอ OTP และการเข้าสู่ระบบ) | คำขอ HTTP | ความปลอดภัย | ประโยชน์โดยชอบ |
| เบราว์เซอร์ | `ck_consent`, `customerSession`, `cake_vid` (sessionStorage) | เบราว์เซอร์ | ความจำเป็น / ฟีเจอร์แบบเค้ก | ดูนโยบายคุกกี้ |
| สถิติคลิก | รหัสผู้เยี่ยมชมแบบสุ่ม + รหัสรูป (`punpang_record_click`) | เบราว์เซอร์ | แนะนำแบบเค้ก | ประโยชน์โดยชอบ |
| โอกาสการสั่ง | `occasion` {kind, consent} ในออร์เดอร์ (เลือกเอง ต้องยินยอม) | ลูกค้า (หน้าสั่งซื้อ) / พนักงาน | สถิติรวมไม่ระบุตัวตนเพื่อแนะนำสินค้า (`computeOccasionStats`, 30 วัน, ขั้นต่ำ 3 ออร์เดอร์ต่อกลุ่ม) | ความยินยอม |
| สถิติการเข้าชม | จำนวนการเข้าชมรวมรายวัน (`punpang_record_pageview(p_day)`) | เบราว์เซอร์ (ไม่มีรหัส/IP ในตาราง) | ดูแลและปรับปรุงร้าน (แดชบอร์ด) | ประโยชน์โดยชอบ |
| สถิติสินค้า | จำนวนการสั่งรวมของสินค้า (`shop_public`: `retailSales`, `retailPairs`) | คำนวณจากออร์เดอร์ | แนะนำสินค้า "ยอดฮิต" และ "ลูกค้าก็สนใจ" | ประโยชน์โดยชอบ (ไม่ระบุตัวตน) |
| แนะนำส่วนตัว | ประวัติการสั่งของลูกค้าเอง (หน้า "สำหรับคุณ") | ออร์เดอร์ของลูกค้า | แสดงให้ลูกค้าเห็นเท่านั้น | ประโยชน์โดยชอบ |
| ตอบแชท AI | ข้อความล่าสุดที่ผ่าน PII gate + ผลตอบ (`punpang_records` collection `aiLog`, ข้อความไม่เกิน 200 ตัวอักษรที่ตัดข้อมูลส่วนตัวแล้ว) | แชท Facebook | ตอบคำถามทั่วไป (เฉพาะเมื่อเปิดใช้) | ประโยชน์โดยชอบ / ตรวจคุณภาพ |

## 3. ระยะเวลาเก็บรักษา (ตามค่าที่ร้านยืนยัน)
- บัญชีและข้อมูลติดต่อ: ตลอดการใช้บริการ + 24 เดือนหลังใช้ครั้งล่าสุด (`retentionAccount`)
- ออร์เดอร์ การชำระ สลิป: 5 ปี (`retentionAccounting`)
- แชท: 12 เดือนหลังข้อความล่าสุด (`retentionChat`; ทำงานโดย `chatSync.purgeOldMessages`)
- โอกาสการสั่ง: เก็บกับออร์เดอร์ ตามระยะเก็บออร์เดอร์ · ลบเมื่อลูกค้าถอนความยินยอม (ต้องมีขั้นตอนลบที่ทำได้จริง ดูข้อ 7)
- สถิติรวม (โอกาส สินค้า การเข้าชม): เป็นตัวเลขรวม ไม่มีรหัสลูกค้า · โอกาสคำนวณจากออร์เดอร์ย้อนหลัง 30 วันเมื่อเรียก
- บันทึก AI (`aiLog`): ยังไม่มีงานลบอัตโนมัติในรีโป ให้ใช้ระยะเดียวกับแชท (`retentionChat`) และต้องเพิ่มงานลบ (ดูข้อ 7)
- OTP: หมดอายุ 5 นาที · บันทึกการส่ง SMS (`punpang_sms_log`) เก็บเฉพาะปลายเบอร์ 4 หลัก
- เซสชันลูกค้า: 14 วันนับจากการใช้งานล่าสุด
- บันทึกการยินยอม: ตลอดเวลาที่เก็บข้อมูลที่เกี่ยวข้อง
- **ยังไม่มีงานลบ OTP/IP/ประวัติ `punpang_tg_log` อัตโนมัติที่ยืนยันได้จากโค้ดในรีโป** ต้องตั้ง pg_cron หรือรายงานเป็นรอบ (ดูข้อ 7)

## 4. มาตรการรักษาความปลอดภัย (ที่มีในโค้ด)
- OTP: แฮช + salt · อายุ 5 นาที · กรอกผิด 5 ครั้งต้องขอใหม่ · ขอใหม่ได้ทุก 60 วินาที · จำกัด 5 ครั้งต่อเบอร์ และ 20 ครั้งต่อ IP ต่อชั่วโมง
- PIN: PBKDF2-SHA256 210,000 รอบ · ห้าม PIN ง่าย · ผิด 5 ครั้งล็อก 15 นาที · จำกัด IP ที่ล็อกอินล้มเหลว 30 ครั้ง/10 นาที
- ข้อความเข้าสู่ระบบล้มเหลวเหมือนกันทุกกรณี ไม่บอกว่าเบอร์มีบัญชีหรือไม่
- ตารางบัญชี/OTP/เซสชันเปิด RLS ไม่มี policy ให้ client เข้าถึงผ่าน service role ใน Edge Function เท่านั้น
- ไฟล์ส่วนตัวเปิดด้วยลิงก์ลงลายเซ็นที่มีวันหมดอายุ (R2 worker `/f/…?exp&sig`)
- Facebook webhook ตรวจลายเซ็น HMAC ด้วย `FB_APP_SECRET` · ตอบ 200 ก่อนแล้วประมวลผลบอทต่อ
- Telegram: จำกัดอัตรา 20 ต่อนาที / 300 ต่อชั่วโมง และไม่เก็บข้อความใน log
- `service_role` และ token ทั้งหมดอยู่ใน secrets เท่านั้น

## 5. สิทธิของเจ้าของข้อมูล และขั้นตอน
- ลูกค้าดู/แก้/ขอลบเองได้ที่ "บัญชีของฉัน" (การลบต้องยืนยัน OTP แล้วรอพนักงานอนุมัติที่ หน้าคำขอลบข้อมูล)
- ขั้นตอนคำขอลบ: ตรวจไม่มีออร์เดอร์ค้างและยอดค้าง → ลบ/ทำให้นิรนามตามหัวข้อ "ลบข้อมูล" ใน `docs/customer-auth.md` → บันทึกผล
- คำขอผ่านอีเมล/แชท: ยืนยันตัวตนก่อน → ดำเนินการภายใน 30 วัน → บันทึกคำขอและผลไว้ (ไม่มีระบบบันทึกคำขออัตโนมัติ)
- ถอนความยินยอมข่าวสาร: ปิดในหน้าบัญชี · คุกกี้: ปุ่ม "ตั้งค่าคุกกี้"

## 6. การละเมิดข้อมูล
1. ตรวจสอบสาเหตุและขอบเขต (ใช้ log ของ Supabase / Cloudflare)
2. หมุนรหัสที่รั่ว (service role, FB_APP_SECRET, SMS/Telegram token) และปิดทางเข้าที่เกี่ยวข้อง
3. ประเมินความเสี่ยงต่อเจ้าของข้อมูล ถ้ามีความเสี่ยง: แจ้ง สคส. ภายใน 72 ชั่วโมง และแจ้งลูกค้า
4. บันทึกเหตุการณ์ในเอกสารนี้
