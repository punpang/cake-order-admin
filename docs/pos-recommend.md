# POS แนะนำขาย · อันดับขายดี · ปรับคะแนน (รอบ I)

- **ชุดบันเดิ้ลที่ใกล้ครบ**: ในตะกร้า POS ถ้ามีบางชิ้นของชุดที่เปิดใช้อยู่ (ตามช่วงเวลา) และชิ้นที่ขาดมีสต็อก จะขึ้น "ชุด … เพิ่ม … ได้ราคาชุด ประหยัด …" กด "เพิ่มให้ครบชุด" (สินค้าที่มีตัวเลือกจะเปิดหน้าเลือกตัวเลือกก่อน) · สูงสุด 3 ชุด เรียงตามประหยัดมาก
- **ลูกค้ามักซื้อคู่กัน**: นับจำนวนออร์เดอร์/บิล POS (ไม่นับร่าง/ยกเลิก) ใน 90 วันที่มีทั้งสินค้าในตะกร้าและสินค้านั้น ต้องซื้อคู่ ≥ 2 ครั้ง · สูงสุด 3 ชิ้น · ไม่แนะนำของที่อยู่ในตะกร้า/หมด/ไม่เปิด POS (ค่าคงที่ใน `src/lib/posRec.js`)
- **ขายดี**: รวมจำนวนชิ้นที่ขายใน 30 วัน (ไม่นับร่าง/ยกเลิก) ติดดาว "ขายดี #n" 5 อันดับแรก (เสมอ = เรียงตามชื่อ) · ปุ่ม "เรียงขายดี" ในกริดสินค้า
- **ปรับคะแนนลูกค้า** (แอดมิน): จัดการ → ลูกค้า → เปิดลูกค้า → "ปรับคะแนน" เพิ่ม/ลด + เหตุผลบังคับ · เพิ่ม = ล็อตใหม่อายุตามตั้งค่า · ลดตัดล็อตเก่าก่อน ลดเกินคงเหลือไม่ได้ · ประวัติ 8 รายการล่าสุดแสดง "ปรับเอง" + ผู้ทำ
- POS ค้นหา/เลือกลูกค้าเพื่อสะสมคะแนน: มีอยู่แล้ว (รอบ B)

## จัดชุดบันเดิ้ล (แก้ไขภายหลัง)

- เดิมระบบเลือกชุดที่ประหยัดมากสุดก่อนแล้วจบ ทำให้ชุดที่ใช้สินค้าซ้ำกันแย่งชิ้น (เช่น BC ประหยัด 10 แย่ง B,C จาก AB+CD ที่รวมประหยัด 18) → ตอนนี้ลองทุกการจัดชุดแล้วเลือกที่ประหยัดรวมมากสุด (ชิ้นหนึ่งอยู่ได้ชุดเดียว · ชุดซ้ำหลายรอบได้ · ใช้ชุดก็ต่อเมื่อประหยัดกว่าส่วนลดรายชิ้นของชิ้นนั้น)
- คำแนะนำ "เพิ่มให้ครบชุด" ไม่นับชิ้นที่ถูกจัดเข้าชุดอื่นไปแล้ว
- แสดงราคาเต็มข้างราคาชุด (รายการโปร/การ์ดแนะนำ) และเตือนในหน้าโปรโมชัน: ราคาชุดไม่ต่ำกว่าราคาปกติ, สินค้าถูกลบ, ชุดที่ใช้สินค้าซ้ำกัน
