# สินค้า POS / สินค้าสำเร็จ · โปรโมชัน · คะแนนสะสม (รอบ B)

## สินค้า
- "สินค้าสำเร็จ" เดิมถูกยกเลิก ย้ายเป็นสินค้า POS (`db.retailItems`) ราคาคงที่ · หน้าจัดการ `/admin/settings/retail`
- ฟิลด์: `images`, `recipe` (สูตรวัตถุดิบ ใช้คิดต้นทุน/ตารางเตรียม), `pinned` (ปักหมุดขายดี), `showInPos`, `showOnStore` (สวิตช์แยกกัน), `description`, `typeId/flavorId/sizeId` (ไม่บังคับ)
- `sizeId` ใช้คิดราคาตัวเลือกแบบ "ตามขนาด" ตอนสร้างออร์เดอร์ (เช่น กล่องพิเศษ) · ไม่มี `sizeId` = ตัวเลือกแบบตามขนาดคิด 0
- สร้างออร์เดอร์/แชท: แท็บ "สินค้าสำเร็จ" เลือกจากสินค้าที่ `showInPos` และไม่มีตัวเลือกหน้าร้านบังคับ (เช่น เครื่องดื่มไม่แสดง)
- ออร์เดอร์เก่า `kind: 'ready'` ถูกแปลงเป็น `kind: 'retail'` (`retailId`, `retailPrice`) ในข้อมูลตัวอย่าง · ของจริงต้องเขียน migration ตอนย้าย Supabase
- หน้าร้านเว็บแสดงเฉพาะสินค้า `active && showOnStore` · ราคาหน้าร้านลดตามส่วนลดรายสินค้า/หมวด/ทั้งร้านที่ใช้อยู่ (ส่วนลดท้ายบิล/บันเดิ้ลไม่นับ)

## โปรโมชัน POS (`/admin/settings/promos`, เฉพาะแอดมิน) — ช่วงเวลา: วันเริ่ม–สิ้นสุด · วันในสัปดาห์ · เวลา (ข้ามเที่ยงคืนได้)
- ส่วนลด `db.posDiscounts`: % หรือ บาท · ขอบเขต สินค้าที่เลือก / หมวด / ทุกสินค้า / ท้ายบิล · ขั้นต่ำ (เทียบยอดสินค้าก่อนลด)
- บันเดิ้ล `db.posBundles`: ชุดสินค้า + ราคาชุด (ต้องต่ำกว่าราคาปกติรวม)
- คะแนนพิเศษ `db.pointPromos`: ตัวคูณคะแนน (×2, ×3) ต่อสินค้า/หมวด/ทั้งร้าน
- กติกา (`src/lib/posPromo.js`): ต่อสินค้า 1 ชิ้นใช้ "อันที่ลดมากสุด" ไม่ซ้อน (ส่วนลดรายสินค้า/หมวด หรือบันเดิ้ล) → ส่วนลดท้ายบิลคิดต่อจากนั้น (เลือกอันที่ลดมากสุดอันเดียว) → คูปอง/ส่วนลดมือ · บันเดิ้ลใช้เมื่อประหยัดกว่าส่วนลดรายชิ้นของชิ้นนั้น · บรรทัดเดียวอาจแตกเป็นหลายรายการถ้าชิ้นได้ส่วนลดไม่เท่ากัน · เก็บส่วนลดใน `item.discounts` (kind `promo` | `bundle`) เป็น snapshot
- ตัวคูณคะแนนหลายโปรซ้อนกันใช้ตัวสูงสุด นับตามเวลาที่สร้างออร์เดอร์

## คะแนนสะสม
- คิดจาก "ยอดสินค้าสุทธิ" (`itemNets`): ยอดรายการหลังส่วนลดรายการ แล้วหักส่วนลดระดับบิล (ปรับราคาติดลบ/คะแนนที่ใช้/คูปอง) แบ่งตามสัดส่วน ไม่รวมค่าส่ง/VAT ไม่ติดลบ · สิทธิ์หมุนกาชาคิดจากฐานเดียวกัน · `pointsFor(order)` ใช้ทั้งตอนให้จริงและตัวอย่างใน POS
- POS: สะสมได้เมื่อเลือกสมาชิก (ค้นหาหรือสมัครที่เคาน์เตอร์: ชื่อ+เบอร์ + ยืนยันว่าลูกค้ารับทราบนโยบาย/เงื่อนไข เก็บหลักฐาน `via: pos`) · **POS ไม่ใช้คะแนนตรง ๆ** ใช้คูปองส่วนลดที่ลูกค้าแลกจากเว็บ (มีขั้นต่ำ/อายุ) · ออร์เดอร์ที่ไม่ใช่ POS ยังใช้คะแนนเป็นส่วนลดในหน้ารายละเอียดได้ตามเดิม
- ของแลก `db.rewards.kind`: `item` (ของรางวัลรับที่ร้าน) | `coupon` (คูปองส่วนลด `amount`, `minSpend`, `validDays`) · กาชาประเภท "ของรางวัล" เลือกได้เฉพาะ `item`
