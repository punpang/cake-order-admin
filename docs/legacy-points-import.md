# นำเข้าคะแนนเดิมจากระบบเก่า

คู่มือสำหรับนำเข้าข้อมูลลูกค้าเก่ารอบใหม่ ใช้คู่กับ `supabase/migrations/20261127410000`–`20261127430000`

## กติกาที่ใช้งานอยู่
- ตาราง `punpang_legacy_points` เก็บ **แฮชของเบอร์ที่ normalize แล้ว** (sha256) ไม่เก็บเบอร์ดิบ
- เบอร์ต้องตรงกับ `normalizeTel` ใน `src/lib/legacyPoints.js` (ตัดสิ่งที่ไม่ใช่ตัวเลข, `66xxxxxxxxx` → `0xxxxxxxxx`)
- คะแนนที่ได้ = คะแนนสุทธิเดิม (บวกหักลบ) × 2 × ตัวคูณระดับสูงสุด ปัดลงเป็นจำนวนเต็ม
- ยอดซื้อสะสม = เกณฑ์ระดับสูงสุด + 1 เพื่อให้ได้ระดับสูงสุด 1 ปี
- ลูกค้าใหม่ที่เบอร์ตรง ระบบจับคู่อัตโนมัติผ่าน trigger และลบแถวเบอร์นั้นทันทีหลังรับสิทธิ์
- สิทธิ์หมดหลัง **31/12/2027** pg_cron ลบเบอร์ที่หมดสิทธิ์ทุกวัน

## ขั้นตอนนำเข้า
1. รับไฟล์ dump (`a_customer`, `customer_scores`) ประมวลผลในเครื่อง ห้ามเก็บไฟล์ดิบในรีโพ
2. คำนวณต่อเบอร์: คะแนนสุทธิ, วันเคลื่อนไหวล่าสุด (จาก `created_at`/`updated_at` ที่ใหม่กว่า), ข้ามเบอร์ไม่ถูกต้อง
3. สร้างคำสั่งนำเข้า **เป็น UPDATE กับเบอร์ที่มีอยู่แล้ว** (`update ... from (values ...) v(h, d) where p.tel_hash = v.h`) ไม่ใช้ INSERT เพราะคอลัมน์ `points` ห้ามว่าง และจะล้ม
4. ตรวจจำนวนแถวและคะแนนรวมให้ตรงกับที่คำนวณในเครื่องก่อนรันจริง
5. แยกเบอร์ที่ไม่เคลื่อนไหวใน 1 ปี แล้วลบ **เมื่อผู้ดูแลยืนยันจำนวนเท่านั้น**
6. เก็บเฉพาะแฮช วันที่ และคะแนน ลบไฟล์ชั่วคราวหลังใช้งาน

## ข้อควรระวัง
- เบอร์ใน `punpang_customers` มีดัชนีไม่ซ้ำ (digits) จึงไม่มีลูกค้าสองคนใช้เบอร์เดียวกัน
- ยืนยันฐานทางกฎหมาย (PDPA) ก่อนนำเข้าทุกรอบ ตามที่บันทึกใน `docs/pdpa.md`
- ปุ่มย้ายคะแนนแบบพนักงานถูกปิดแล้ว การให้คะแนนเกิดขึ้นผ่าน trigger เท่านั้น
